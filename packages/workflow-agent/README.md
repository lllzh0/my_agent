# My Agent · OMP 入口

面向编程与资料研究的产品入口，使用当前 fork 内的 OMP SDK 和终端界面。当前版本是 **0.2.0、本地源码试用版**。它已迁入显式资源、受控工具、研究来源、后台任务、直接文本恢复和 MCP 外部工具接入；完整工作流预设切换与 GUI 尚未实现。

第一阶段面向有一定编程基础的 TUI 使用者，允许编辑配置、设置环境变量并手动执行恢复命令，不要求完整配置向导或会话恢复界面。最新验收范围见 [TUI 范围修订](../../docs/workflow-agent-phase1-scope.md)。

## 在当前工作区启动

已验证环境：Bun 1.3.14、macOS arm64、OMP 18.10.3。当前 checkout 的依赖、官方同版本原生组件和生成文件已经准备好：

```sh
cd my_agent
bun run agent --demo
```

新 clone 的源码先运行 `bun run agent:prepare`。它按锁文件安装产品和工具视图生成器的依赖、生成视图、下载并校验同版本官方原生组件，不执行依赖安装脚本。需要访问 npm registry，当前只验证了 macOS arm64；这是使用预编译组件的源码启动流程，没有编译 Rust。此包依赖同仓库 workspace，不能直接当作独立 npm 包安装。

`--demo` 只返回固定的本地模拟回答，可检查界面、菜单、会话保存与恢复，不代表真实模型能力。输入 `/agent` 打开主菜单，`/quit` 退出。退出后显示的完整恢复命令可以直接运行。

指定工作目录、使用轻量模式或取得一次回答：

```sh
bun run agent --demo --cwd /你的项目目录
bun run agent --demo --light
bun run agent --demo --print --prompt '你好'
```

`--cwd` 控制模型工具和终端状态栏的工作目录；优先级为显式 `--cwd`、`MY_AGENT_CWD`、启动目录。`--light` 不加载选定的工作流指令、技能或工具，适合纯问答。`--print` 没有交互批准者，因此默认拒绝写入和命令执行。

## 配置真实服务

```sh
bun run agent setup --defaults
bun run agent doctor
```

默认配置在 `~/.my-agent-omp/config.json`。使用 `--home /绝对路径` 或 `MY_AGENT_HOME` 可指定另一个独立目录；会话、资源清单、来源、任务和恢复记录保存在同一目录内。不会自动导入旧 Pi 配置或会话。`setup --defaults` 保存当前有效配置，首次运行时使用默认值，不覆盖已有配置为出厂值。

在自己的终端设置环境变量，密钥不要发送到聊天中：

```sh
export OPENCODE_API_KEY='你的 OpenCode Go 密钥'
export TAVILY_API_KEY='你的 Tavily 密钥'
bun run agent doctor
bun run agent --cwd /你的项目目录
```

默认模型配置为 `provider: opencode-go`、`id: deepseek-v4.1-flash`；搜索为 Tavily。配置只保存密钥的环境变量名。`doctor` 仅检查配置、运行时与依赖，不发送模型或搜索请求，也不证明真实连通性。真实服务、地区可用性、额度限制及任务质量尚未验证。

OpenCode Go 要求的 `x-opencode-session` 已由 OMP 自动附加：同一会话的工具调用和恢复沿用同一个 ID，新会话使用新 ID，轻量模式也会携带。当前客户端 `User-Agent` 为 `omp/18.10.3`。无需在配置中手填固定请求头；官方要求和实际请求验证见 [OpenCode Go 请求头核对](../../docs/workflow-agent-opencode-go.md)。

若模型长时间停在“思考中”，可以按 Esc 取消，再正常退出。错误或取消会将最近一次异常的响应摘要保存到 `<配置目录>/state/<会话 ID>/model-stream.json`，对照收到的完整 SSE 事件（服务逐段推送的响应）、结束标记和 agent 解析出的字符数。摘要不含密钥、请求头或正文；缓冲区淘汰、截断和未形成完整事件的数据会限制判断，不能仅凭“没收到数据”断定服务端或网络故障。查看 [读取后停顿调查](../../docs/workflow-agent-read-stall.md)。

不使用 Tavily 时可以不设置 `TAVILY_API_KEY`，改用下文的 Exa MCP。内置 `web_search` 仍调用 Tavily，不会自动换后端。

模型、读取范围和命令联网域名目前通过配置文件编辑，重启生效。旧 `model.authPath` 凭据文件、模型 OAuth 登录和第三方代码扩展尚未接入；遇到这类启用配置会明确拒绝启动。MCP 可通过菜单配置，单个服务配置无效只影响该服务；轻量模式不连接任何 MCP。

## 显式选择资源

在 `/agent` → “修改资源选择”添加指令文件、技能目录或清空选择；也可编辑配置的 `resources` 部分，例如：

```json
{
  "instructions": ["/绝对路径/coding/AGENTS.md"],
  "skills": ["/绝对路径/coding/skills"],
  "extensions": [],
  "appendSystem": []
}
```

保存后重启才会应用，当前会话继续使用启动时的清单。技能可以选择单个 `SKILL.md`、含该文件的技能目录，或包含多个技能的目录；重名技能会报错。可用 `/skill:技能名称` 显式调用。技能名称与原生命令相同也不会放行原生命令。

未选择的祖先、项目或全局 AGENTS/SYSTEM/技能/代码扩展不自动进入模型请求。技能通常只先提供名称、说明和路径，正文在需要时读取。资源清单中的 `bodyLoaded` 记录产品 `read` 工具是否读取过技能文件，并非所有原生技能调用路径的完整 token 审计。

“不自动加载”不等于“禁止模型主动读取”：允许范围内的普通文件仍可通过读取工具打开。显式选择的指令/技能文件应由用户维护；文件发生变化后，恢复检查会要求使用匹配版本或新开会话。

## 常用操作

| 入口 | 行为 |
|---|---|
| `/help` | 查看与输入补全一致的产品命令表；补全只显示已接入的命令和所选技能 |
| `/agent` | 查看实际资源、工具、权限、研究来源、后台任务、文件差异与恢复、任务进度；配置和连接 MCP |
| `/context`、`/tools` | 查看估算的上下文占用及实际资源、工具清单 |
| `/effort [强度]` | 查看当前模型支持的思考强度；仅修改本会话，不保存全局默认值 |
| `/retry`、`/redo` | 同一个重试入口，续接上一轮失败或中断的回答；成功的回答不会重跑 |
| `/undo` | 撤销最近一轮尚未恢复的直接文件修改；先预览，再批准，聊天记录保留 |
| `/fresh` | 重建模型连接状态，保留本地聊天和产品会话；不自动请求模型 |
| `/usage` | 查看当前会话累计 token 与估算费用；不查询账户额度或消耗重置机会 |
| `/jobs`、`/jobs output <id> [cursor]`、`/jobs stop <id>` | 查看产品后台任务、按游标读取日志或停止托管进程 |
| `/todo`、`/mcp` | 查看产品任务进度，或打开已有受控 MCP 菜单 |
| `/plan`、`/agent-plan` | 在只读计划与执行模式间切换；切换时清除会话授权 |
| `/compact [soft] [关注内容]` | 使用 OMP 摘要压缩；真实模式可能产生模型请求。当前不开放 `remote` 和 `snapcompact` |
| `/skill:名称` | 调用本次选择的技能 |
| `/session [info]`、`/hotkeys` | 查看会话信息、快捷键；不开放会话删除或 OAuth 账户绑定 |
| `/quit`、`/q` | 关闭 MCP、清理本会话托管命令并退出，显示产品恢复命令 |
| `--resume 会话文件` | 恢复同一配置目录、同一工作区且资源签名一致的产品会话 |

新会话默认进入执行模式，但每次写入或命令仍需批准；计划模式是本次进程状态，恢复会话后需重新开启。恢复使用退出时打印的产品命令，不使用原生 `omp --resume`。模型、资源或权限配置变化后建议新开会话。

`/redo` 只表示重试，不能恢复被 `/undo` 撤掉的内容。一次 `/undo` 按一次 agent 运行产生的修改分组（重试算新的运行）；重复执行会继续恢复更早的未撤销轮次，无文件修改的回答会跳过。只覆盖已经进入文件记录的 `write`、`edit`、`write_report` 文本修改；恢复起点包括该轮开始前已有的人工编辑。shell、Git、MCP 和外部服务操作不会回滚，重试前应核实结果未知的外部操作。

文件被继续编辑时拒绝覆盖；预检发现冲突时不写入任何目标。会话忙碌、有排队消息、后台命令正在启动或运行，以及计划模式下均拒绝恢复。多个文件恢复并非磁盘事务：若执行过程中出错，可能只完成一部分，会报告已恢复文件并保留备份。后续模型请求会收到实际恢复文件的通知，命令本身不会自动请求模型。详细验证和上游方案比较见 [基本命令与撤销](../../docs/workflow-agent-basic-commands.md)。

撤销后再重试会保留已完成或失败的工具结果及撤销通知，由模型根据恢复后的文件状态继续处理；不会直接重放旧文件操作。立即取消重试也保留撤销通知。没有撤销通知的普通重试继续沿用 OMP 的原生续接。

同一会话被另一个进程占用时拒绝恢复；先退出原进程，再执行 `--resume`。产品会话不沿用原生自动换 ID 的冲突恢复方式，以免历史与修改、任务、来源记录分离。

未适配的原生命令和快捷键已关闭，包括原生模型切换、会话切换、外部编辑器、子 agent、MCP 重载、`!` 命令与 Python 直达入口。可以让模型使用产品提供的 `bash` 工具执行获批命令。

## 编程与研究能力

当前模型工具：`read`、`write`、`edit`、`grep`、`find`、`ls`、`bash`、`job_output`、`job_stop`、`web_search`、`web_fetch`、`read_document`、`write_report`、`task_list`、`task_update`、`ask_user`、`mcp_list`、`mcp_call`。

文件读取和编辑复用 OMP 原生能力，外层检查真实路径与授权。只接受普通路径；行范围使用 `offset`、`limit`，不接受原生 URI、路径内选择器或通配符。`grep` 是有数量上限的字面文本搜索，`find` 以文件路径子串匹配，暂不等同完整 ripgrep/glob 搜索。

研究工具区分“搜索发现”和“已取到正文”。只有已读取来源才能作为报告的事实引用；推断需明确标记。这是来源记录检查，不会自动证明结论准确或与原文一致。支持网页、Markdown、TXT、JSON、CSV 和文本 PDF；PDF 保留页码，扫描 PDF 暂不支持 OCR。资料限 5 MB，提取及传给模型的正文有长度上限，不能当作全文阅读。网页不能访问本机/私有网络。

## 连接 MCP 外部工具

MCP 是接入其他程序所提供工具的协议。打开 `/agent` → “MCP 外部工具”，可以添加远程 HTTP 服务或本地 stdio 服务（通过程序输入输出通信），查看状态、连接、查看工具及断开。添加、启用或停用配置后重启生效；保存和启动都不会自动连接。

首次连接需要批准，实际工具调用按完整参数另行批准；会话许可只复用完全相同的请求。计划模式禁止连接和调用，轻量模式没有 MCP 工具。连接失败、超时或取消后不会自动重放业务操作，需先核实外部结果再决定是否重试。

表单只填写密钥的环境变量名，密钥在启动终端设置。本地程序必须已经安装，工作目录固定为当前项目，并使用产品沙箱和受控环境变量。远程只支持 Streamable HTTP，外部地址必须是 HTTPS；本机可用 HTTP。OAuth、旧 SSE 和自动安装尚未接入。

配置例子、常见失败原因、权限边界和本轮验证见 [MCP 使用与实现记录](../../docs/workflow-agent-mcp.md)。

免搜索密钥试用可以将下列内容合并到配置的 `mcpServers`，并保持 `permissions.allowNetwork: true`：

```json
{
  "exa": { "type": "http", "url": "https://mcp.exa.ai/mcp", "enabled": true }
}
```

重启后按需批准连接，用 `mcp_list` 查看当时的工具参数，再用 `mcp_call` 搜索。本轮实际通过 `web_search_exa` 搜到 Bun 官方文档，随后用产品 `web_fetch` 读入来源 S1 并保存报告样本。搜索结果不会自动变成已读证据；免密钥服务仍可能限流。用户配置未被自动修改，完整记录见 [本地交付与验证](../../docs/workflow-agent-delivery.md)。

## 权限、后台和恢复边界

- 允许范围内的读取、获准的研究联网默认不弹窗；写入和命令按实际请求批准，可仅批准一次或复用本会话完全相同的请求。计划模式禁止项目写入和命令，但仍可更新产品内部任务记录。
- `permissions.allowNetwork` 控制工具联网；命令及本地 MCP 还需配置 `sandbox.allowedDomains`。默认域名列表为空，所以本地执行不能联网。模型和搜索凭据不会自动传给命令或本地 MCP；MCP 只额外传入显式选择的变量。
- 命令使用 macOS 沙箱；初始化或格式检查失败时拒绝执行。限制常见凭据、产品状态目录、工作区外写入和未允许网络。沙箱运行时固定为 0.0.50，升级必须复测最终规则顺序。本入口只验证了 macOS，不宣称所有宿主能力都在 OS 沙箱内。
- 同时最多 4 个命令，包含等待批准或准备中的请求。日志保留上限为 256,000 字符，支持游标读取。取消和正常退出终止进程组；已经发生的文件或服务副作用不会自动撤销。崩溃后将旧运行记录标为中断，不按历史 PID 杀进程，也不自动重跑命令。
- 命令主进程结束时会清理同组剩余子进程。需要长期运行时，让模型使用 `bash` 的 `background: true` 托管前台命令，不用 `命令 &` 留下独立后台进程。
- 主进程退出后若输出管道仍被脱离进程组的后代占用，最多再等 1 秒便结束管道等待；这不保证终止主动脱离原进程组的程序。
- 直接写入、替换编辑、报告保存只覆盖工作区内至多 1,000,000 字节的普通 UTF-8 文本。最终内容超限会在落盘前拒绝。`permissions.writeRoots` 沿用旧配置字段，当前不能据此扩展产品的直接写入或命令写入范围，请保持为空。
- `/undo` 按轮恢复，菜单支持逐次查看差异和恢复；两者共用批准、计划模式和忙碌检查。目标又有变化时拒绝覆盖。shell、MCP 修改、链接文件、二进制、大文件和外部编辑器不属于通用撤销范围。操作时应暂停其他程序对目标文件的并发写入。

若配置损坏且存在最近有效备份，可运行 `bun run agent restore-config`，同样传入原来的 `--home`。损坏原件会单独保留。

## 本地诊断

```sh
bun run agent diagnose
bun run agent diagnose --output /你选择的新路径/diagnostic.json
```

`diagnose` 默认在终端预览，只有指定 `--output` 才保存文件，已存在的文件不会覆盖。可以继续使用 `--home`、`--cwd` 选择配置及项目。即使配置损坏，诊断也会输出受控的配置错误提示，不改坏文件。

报告包含版本、运行环境、已识别的模型名称、凭据是否存在、所选资源数量、MCP 配置数量、沙箱依赖状态和近期错误类别，不包含任意自定义模型字段、密钥、配置路径、提示词或文件与会话正文。资源只检查存在性，不代表内容有效；不连接模型、搜索或 MCP，也不证明服务可达。需要分享时使用 `diagnose`；`doctor` 是供自己查看的环境信息，仍含本地路径。

会话在本地保留最近 200 条错误元数据；报告从更新时间最近的 20 个错误文件中选最近 200 条。分类覆盖鉴权、权限、限流、网络、超时、取消、解析、配置和未知错误。诊断写盘失败不改变原操作结果；超时或断网也不代表外部写入一定没有发生，继续前先核实实际状态。

若看起来卡在文件读取，先核对会话里的 `read` 是否已有成功结果：工具完成后还需等待模型继续回答。当前 DeepSeek 接入在没有环境变量覆盖时，连续无进展的默认流等待为 300 秒。可在启动终端设置 `PI_OPENAI_STREAM_FIRST_EVENT_TIMEOUT_MS=90000`（首个有效响应）和 `PI_OPENAI_STREAM_IDLE_TIMEOUT_MS=60000`（后续连续无进展），再重启或执行原恢复命令；这不是整项任务的总时限，自动重试也会延长整轮等待。具体停流调查见 [probe 调查记录](../../docs/workflow-agent-read-stall.md)。

## 复跑与当前限制

从 fork 根目录执行：

```sh
bun run --cwd packages/workflow-agent check
bun test packages/workflow-agent/test
MY_AGENT_SANDBOX_TEST=1 bun test packages/workflow-agent/test
```

普通测试默认跳过三项真实沙箱测试；最后一条需在普通 macOS 终端运行。在 Codex 等外层沙箱中嵌套 `sandbox-exec` 可能被系统拒绝，不能因此关闭产品隔离。全部测试使用临时文件和本地模拟服务，不需要真实密钥。

干净源码副本已用独立 HOME 和空 Bun 缓存跑通 `agent:prepare`、setup、doctor、diagnose、离线问答及命令恢复；删除源码副本后，独立用户目录中的配置和会话仍保留。此证据不代表独立安装包、升级迁移或真实模型任务验收。

入口迁移证据见 [迁移记录](../../docs/workflow-agent-migration.md)，后续 MCP 证据见 [MCP 记录](../../docs/workflow-agent-mcp.md)，最新结果见 [本地交付与验证](../../docs/workflow-agent-delivery.md)。真实模型、Tavily、其他用户所选 MCP 的业务调用、第三方代码扩展、完整预设管理、跨平台、打包、GUI 和六项真实任务验收仍未完成。
