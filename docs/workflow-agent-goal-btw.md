# 目标模式与旁问

2026-10-17。产品入口已接入 OMP 18.10.3 自带的目标模式和 `/btw`，不需要安装新插件。正常重启 `bun run agent` 后即可使用；两项命令只用于交互终端，`--print` 会明确拒绝它们。

## 让 agent 围绕一个目标继续工作

```text
/goal set 找到这个项目的测试失败原因，修好并运行相关测试
/goal show
/goal budget 50000
/goal pause
/goal resume
/goal drop
```

| 命令 | 作用 |
|---|---|
| `/goal set 目标` | 建立目标并开始第一轮；已有活动目标时更新目标并开始新一轮 |
| `/goal 目标` | 没有目标时的快捷写法 |
| `/goal` | 已有目标时打开管理菜单；没有目标时打开目标输入框 |
| `/goal show` | 查看状态、用量及预算 |
| `/goal budget 正整数` | 调整活动目标的 token 预算；`off` 取消预算 |
| `/goal pause` | 暂停自动续跑，保留目标 |
| `/goal resume` | 恢复暂停的目标 |
| `/goal drop` | 确认后放弃当前目标 |

普通回答结束后，OMP 会按目标状态安排下一轮，而不是每次都等你输入“继续”。已经完成、受到预算限制、等待条件或连续没有进展时，会按原生规则停止或抑制续跑；它不保证所有目标都能自动完成。模型可以查看目标、报告完成，不能自行换目标、改预算、恢复或放弃目标。完成是否符合实际，仍需要检查结果。

预算默认不设上限；`/goal set` 会立即开始第一轮，之后设置的预算不表示第一轮开始前已经有上限。预算按 OMP 收到的用量计算：输入、输出和缓存写入计入，缓存读取不计入；用量在响应后汇总，可能超过设定值。它不是账户额度或所有协作、审核、旁问请求的统一费用上限，不能当成供应商侧硬限额。

目标模式继续使用当前 manual / auto / full 权限和受控工具，不会自动取得完整权限。用户后来追加的限制会保留在授权审核上下文中。已有活动目标时，先 `/goal pause` 再切换 `/plan`；计划模式不能启动或恢复目标。`--light` 没有目标工具，因此不提供目标模式。

目标保存在当前会话中。退出后通过 `/resume` 或产品的 `--resume` 恢复，会先进入暂停状态，需要人主动 `/goal resume`。冷恢复时从已保存的目标补回审核任务说明，同一进程内恢复则保留最近的人类限制。恢复为暂停状态时，原生 `goal` 查看工具可能仍在工具列表中，这不会自动启动模型或允许模型自行恢复目标。

## 工作途中问一个旁支问题

```text
/btw 你刚才为什么选 SQLite？有什么替代方案？
/btw
```

`/btw 问题` 用当前模型和主会话当时的上下文回答问题。主任务可以继续运行；旁问和回答保存在独立历史中，不追加到主聊天，也不改主任务、当前目标或授权上下文。它只回答，不执行工具；即使模型返回写文件等工具调用，也会丢弃调用。旁问可能缺少主任务稍后才取得的资料。

直接输入 `/btw` 打开旁问历史。OMP 原生面板支持上下选择、Tab 切换详情、`f` 或 Enter 追问、`c` 复制，Esc 关闭；在旁问正在生成时，Esc 先取消旁问，主任务不因此取消。一个旁问尚在运行时，不接受新的旁问请求。历史随当前会话恢复，普通主聊天导出不包含这些独立记录。

轻量模式也可以旁问。旁问使用当前服务并可能消耗模型额度；它沿用已选的系统说明和技能目录，不是另一套工作流预设。为复用提示缓存，请求可能仍携带工具定义，但没有工具执行循环。产品继续拦截原生分支提升，不能从旁问绕过产品会话管理。

## 复用范围与改动

| 部分 | 采用的现有实现 | 产品补充 |
|---|---|---|
| 目标状态、保存、预算、续跑和停止条件 | OMP `GoalRuntime`、`GoalTool`、原生 `/goal` | 受限工具集显式允许隐藏 goal；只允许模型查看/完成；衔接权限和计划模式 |
| 输入与自动续跑 | OMP `getUserInput`、`submitInteractiveInput` | 产品启动原生输入循环；宿主关闭时通过可选取消信号结束等待 |
| 旁问、面板、追问及历史 | OMP `BtwController`、`runBtwTurn`、`runEphemeralTurn` | 命令路由放行，保留产品分支/会话边界 |
| 底座缺陷修复 | 继续修改原位置 | 暂停/完成后恢复原工具集；严格校验预算数字；修复关闭恰逢目标收尾时的等待竞态 |

本轮没有另写一套目标调度器、旁问模型客户端或历史存储，也没有复制 Claude Code 的私有实现。旁问体验参考其[官方交互说明](https://code.claude.com/docs/en/interactive-mode#side-questions-with-btw)，具体界面与恢复行为沿用本地 OMP。

## 验证和试用

离线自动检查覆盖目标启动/完成、自动续跑、暂停/恢复、预算输入、计划边界、模型越权、冷恢复审核上下文、后续人类限制和退出竞态；旁问覆盖主上下文、历史恢复、主任务并发、取消隔离、丢弃工具调用和分支保护。准确数量与未验证项见 [验证摘要](verification/goal-btw-2026-10-17.json)。测试使用本机假模型，不消耗真实模型额度。

真实服务试用建议：

1. 在临时项目中启动产品，输入 `/goal set 创建 goal-probe.txt，内容为 GOAL_OK，读回确认后结束目标`，检查文件及 `/goal show`。
2. 给一个需要多步的目标，使用 `/goal pause`，确认不再自动续跑；退出、恢复会话，确认仍需 `/goal resume`。
3. 主任务工作时输入 `/btw 用两句话解释当前方案`，查看旁问，再 Esc 关闭，确认主任务继续；恢复会话后用 `/btw` 查看历史。

自动测试不能代替真实模型的工具遵循、目标完成判断、服务限流和长期任务质量，也不代表用户已验收。
