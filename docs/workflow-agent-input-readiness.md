# 启动输入与技能命令分离

2026-10-25，本地源码改动；尚未提交或发布。

## 使用方式

- 启动后等到“输入已就绪”再输入。提前到达的按键会被忽略，不会自动提交；观察到已丢弃输入时会提示重新输入。
- 输入 `/` 查看普通命令；输入 `$` 查看当前启用的技能。
- 输入 `$brainstorming 帮我梳理这个功能` 调用技能。Tab 补全技能名，继续填写需求后回车提交。
- 旧 `/skill:brainstorming` 会提示改用 `$brainstorming`。导入、复制/链接、启用和停用方式不变；资源 ID 仍为 `skill:brainstorming`。
- `$` 作为交互消息的首个 token 生效。句中的 `$HOME`、`$brainstorming` 和普通金额文本不触发技能。

## 原因与修复范围

真实 PTY（由程序驱动的终端）复现了启动时立即发送 `/trace on\rEARLY_QUESTION\r`，随后回车出现 `/trace` 用法错误的情况。启动前终端仍处于按行接收输入的模式，积压的换行进入编辑器后形成一条多行草稿；界面开始接收输入也早于产品初始化结束。命令解析本身不需要修改。

产品在初始化前关闭按键入口，初始化完成后等待输入安静 50 毫秒，再清理尚未完成的按键/粘贴序列并开放输入。就绪检查最长 2 秒；持续输入没有停止时退出并提示重试。异常路径也停止界面、恢复终端模式。

技能调用在产品输入处理层转换为 SDK 已有的技能加载请求，继续复用技能正文读取、附件和排队机制。技能补全使用同步候选，避免快速输入名称后立即按 Tab 时选中旧候选或丢失补全。共享编辑器增加可选的同步补全接口；未使用该接口的宿主保持原行为。

## 实测记录

真实终端使用本机已导入的 brainstorming 的临时副本、独立配置目录和离线演示模型，未修改用户技能或调用收费服务：

- `/` 菜单含 `help` 等命令，不含 brainstorming；`$` 菜单含 brainstorming。
- 在同一批输入中发送 `bra` 和 Tab，正确补全 `$brainstorming`。
- 两次技能调用均产生 `skill-prompt` 消息；启动前的 `EARLY_QUESTION` 没有进入会话。
- 手动开启 `/trace` 后只新增一条记录，含技能正文和 `TRACE_SKILL_SMOKE` 参数，证明早期 `/trace on` 未被执行。
- 持续发送启动输入时按预期退出，未显示就绪；终端的按行输入与回显均恢复。
