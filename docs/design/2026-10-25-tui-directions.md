# My Agent：三套 TUI 候选设计

## 设计依据

My Agent 的核心用途是编程与资料研究，并重视资源选择、操作记录和失败恢复。界面需要让用户随时回答四个问题：现在做什么、用了什么、改了什么、结果有何依据。

已核对以下材料，并以现有源码修正文档中的历史状态：

- 原第一阶段方案：`/Users/ly/Desktop/my_agent/docs/superpowers/plans/2026-10-11-phase-1-agent-implementation.md`。编程、研究和恢复是三条日常流程，业务状态应与终端展示分开。
- `docs/workflow-agent-phase1-scope.md`：面向有编程基础的人，允许命令和配置文件，不必把所有操作做成配置向导。
- `packages/workflow-agent/README.md` 与当前 `src/tui/`：已有资源热切换、外部技能导入、模型切换、恢复、差异与审查、请求轨迹；`/` 和 `$` 已分开。
- `docs/superpowers/specs/2026-10-20-phase2-presets-design.md`：命名工作流预设仍为提案；不能把预设切换画成当前已经可用的能力。当前主线是单 agent，团队分支不混入这次默认界面。
- `src/runtime/state.ts`：任务、文件修改、来源、后台命令、权限、会话、资源和请求轨迹已有各自状态。展示尽量读取这些已有状态，不从模型叙述猜测执行成功。
- `docs/tui.md` 与扩展接口：已有自定义页头、页脚、编辑器、补全及覆盖面板；持久的侧栏和任务式历史需要额外布局接入，不能当作换颜色即可完成。

目前产品主要替换了页头和状态栏，其余大量展示继承 OMP。以下方案同时调整信息顺序、工具结果密度和交互位置。

## 共同规则

1. 对话正文是主内容。连续读文件、搜索和命令输出先显示简短结果，可展开原始记录；错误和待确认项不自动折叠。
2. 工作区、当前会话、计划/执行和授权方式位置稳定。模型与用量放次要位置，token/s 和首字等待时间按轮显示，不占满页头。
3. 输入 `/` 只出现产品命令；输入 `$` 只出现当前启用的技能，Tab 补全后可填写需求。技能选择不隐式启用未选资源。
4. 启动时明确显示“初始化中”；沿用现有丢弃早期输入的规则，就绪后显示“输入已就绪”。生成中要区分“排队补充”和“停止”，不把 Enter、Esc 的含义藏起来。
5. “已选资源”展示实际生效内容。指令、技能、工具、MCP 分组，MCP 的已配置与已连接分开。技能出现在可用列表，不等于正文已进入每一次请求。
6. 确认操作时优先说明要做什么、作用范围和本次授权；确认期间保护已有输入草稿。拒绝后显示未执行，不能继续画成成功。
7. 研究来源区分已读正文、仅读片段和搜索摘要；引用可追溯到已保存来源。文件区分修改成功、检查通过和人工接受。
8. 请求轨迹默认关闭，只由人开启。对比入口是读取已有记录，不发送额外模型请求。
9. 只用终端可实现的等宽文字、细分隔线、有限颜色和字符状态标记。颜色以外还保留文字/符号；不依赖图像协议、圆角、动画或特殊图标字体。
10. 正常小问题不强制创建计划。没有结构化任务时，不凭空生成四步流程或完成百分比。

## 留白：对话优先

主布局是单栏：紧凑页头 → 用户与 agent 对话 → 一条可展开执行摘要 → 输入区 → 低对比状态栏。

特点：

- 页头只留工作区、会话和关键运行状态。
- 已完成的工具调用合并为“已检查 2 处代码 · 已修改 1 个文件”，按需查看明细。
- 文件、来源和资源采用临时展开区，收起后恢复阅读空间。
- 待确认项就近出现于当前执行位置，避免用户视线在屏幕两端跳动。

适合：长对话、设计讨论、研究报告、较窄的终端。

代价：经常对照文件或来源时，需要反复展开；常驻信息少，观察长任务不如另外两套。

接入估计：三套中较小。可优先使用现有页头、页脚、编辑器和工具展示能力；工具记录折叠仍需验证与历史滚动、复制和流式输出的兼容。

## 工作台：对话与依据并排

主布局是约 70/30 的两栏：左侧对话，右侧检查区；输入区横跨底部。右侧在“任务、文件、来源、轨迹”之间切换，一次只展示一类。

特点：

- 对话里的“查看修改”直接打开对应文件记录；研究任务同一位置打开对应来源。
- 任务页显示当前步骤和待办；文件页显示变更及检查状态；来源页显示读取范围；轨迹页显示是否开启及记录对比。
- 常用结果保持可见，同时保留连续的对话阅读体验。
- 会话恢复继续走现有 `/resume`，资源继续走 `/resources`；第一版不再添加一个常驻左侧导航栏挤压正文。

适合：日常编程与研究混用、经常核对操作依据、较宽终端。**这是当前推荐的默认方向。**

代价：占用横向空间，终端布局与焦点控制复杂度较高。草案以约 112 列作为显示双栏的起点；更窄时改为可切换检查面板，具体门槛在真实终端原型中验证。

接入估计：三套中较大。持久侧栏不能只靠现有 editor 区域的 custom 组件实现；需要在现有渲染器上增加产品布局接入点，继续复用会话、权限和编辑器，不另写终端底层。

## 行程：任务步骤优先

主布局围绕一个当前任务展开：目标 → 来自真实任务状态的步骤列表 → 当前步骤的结果与下一动作 → 输入区。历史对话作为可展开内容保留。

特点：

- 已完成步骤压成一行，正在处理的步骤展开，未来步骤明确未开始。
- 编程步骤可以呈现定位、修改、检查、交付；研究步骤呈现问题、搜集、核对、结论。它们只是示例，不强制套用模板。
- 每一步直接关联原有工具记录、文件或来源；失败停留在该步，说明可继续的条件。
- 没有明确步骤时回到普通对话布局，不强行把闲聊做成项目。

适合：多步骤修复、较长的资料整理、持续目标；最容易看清“卡在哪一步”。

代价：依赖准确的结构化任务状态；自由讨论与频繁改方向时容易显得重。必须避免把模型说“完成了”直接渲染为已验证。

接入估计：中到大。需要把已有会话与任务事件投影成步骤视图，保留原历史以便查看、恢复；展示分组不能改写真实会话或执行顺序。

## 对比与推荐

| 维度 | 留白 | 工作台 | 行程 |
| --- | --- | --- | --- |
| 优先让用户看见 | 对话与结论 | 对话及操作依据 | 当前步骤与阻塞点 |
| 文件/来源查看 | 临时展开 | 常驻检查区 | 归入对应步骤 |
| 长文本阅读 | 最舒展 | 正文宽度略受限制 | 需展开对话内容 |
| 窄终端 | 最自然 | 检查区需收起或切换 | 列表可纵向压缩 |
| 实现范围 | 较小 | 较大 | 中到大 |

建议选“工作台”为主要方向，吸收“留白”的低噪声工具摘要；“行程”先作为长任务的候选展示，不同时维护三套完整产品界面。最终取舍仍由用户对预览的反馈决定。

视觉上可以统一一套低饱和终端色板：正文高对比、次要信息低一档、绿色表示已完成、暖色表示待确认。预览中三套强调色不同只是帮助区分，布局选择不绑定配色选择。

## 预览与验证边界

本轮交付的是可交互设计预览。任务内容、资源清单和指标为示例；技能菜单、命令菜单、Tab 补全、检查区、步骤展开和确认交互均只改变预览。不会发送模型请求、执行命令、导入技能或改变真实授权。

浏览器中检查了三套布局、技能补全、文件面板、确认拒绝、轨迹样式和步骤展开。浏览器效果不能证明终端字宽、中文输入法、鼠标选择、滚动恢复、流式输出或平台兼容；这些要在选定方向后用真实 TUI 原型验证。

接下来应冻结一套默认布局、常用终端宽度及三种关键状态（空闲输入、执行中、等待确认），再做最小终端原型。保留当前界面作为开发期回退，先通过启动输入、技能调用、会话恢复和权限确认回归，再接入全部工具展示。
