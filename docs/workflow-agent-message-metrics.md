# 默认内置消息统计

main 和 `codex/team-scheduler-wait` 的产品入口都默认开启 OMP 原生消息统计。正常模式与 `--light` 均生效，无需安装或配置额外插件。

每条模型回复结束后，其下方的统计条显示输出速度和首字等待时间；有工具调用时，每次模型回复分别计算，工具执行耗时不会混进下一条模型消息的 TPS。读取工具的统计可能收进原生读取组，位置沿用 OMP。恢复会话会按已保存的消息数据重新显示，不额外请求模型。

| 指标 | 含义 |
|---|---|
| 吞吐图标后的 `…/s` | 平均 TPS（token/s）：本条消息的输出 token 数除以整次模型请求耗时，包含首个输出前的等待；不是只计算首字之后的生成速度 |
| 时间图标后的 `…s` | TTFT（首个输出等待时间）：从原生模型请求开始，到首个正文、思考或工具调用输出块；不一定是首个正文汉字 |
| 输入、输出、缓存计数 | 服务返回的本条模型消息用量，沿用原生显示 |

统计读取 OMP 的 `usage.output`、`duration`、`ttft`，保存在原有消息记录内。它衡量模型请求，不是从按 Enter 到完成整个任务的总耗时。服务没有提供用量时原生统计条可能不出现；缺少计时信息的旧记录或耗时过短的请求会省略相关指标，不补造零值或估计速度。

实现是在产品的内存设置中默认打开 `display.showTokenUsage`，复用现有计时、TUI 显示和恢复逻辑。不会加载用户未选择的扩展，不会写入全局 OMP 设置，也不向模型追加提示词。`--print` 沿用原有纯文本输出，统计条属于交互 TUI。

自动检查使用 localhost 模拟模型覆盖：普通/轻量模式、真实消息 token/计时到原生统计条、跨进程恢复不额外请求、工具调用和最终回答分别统计、缺用量时不虚构 TPS。原生实时消息和历史消息的统计位置回归另行运行。未使用真实模型服务或进行人工终端视觉验收。
