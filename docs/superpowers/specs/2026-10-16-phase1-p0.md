# 第一阶段 P0：日常开发与研究

用户已要求继续全部 P0，并明确选择完整授权等同 Full Access：取消逐项审批，放开命令沙箱、工作区和网络限制。仍不进入第二阶段预设或 GUI。

## 验收范围

1. 手动、自动、完整三种授权。旧配置默认手动；`/permissions` 和 CLI 显式选择。完整授权仅当前进程，由人选择，不允许模型工具切换，不从旧会话自动恢复。计划模式独立保持只读。切换时必须空闲、没有排队消息或托管后台任务，清空旧批准。
2. 自动模式保留沙箱。工作区普通直接文本修改可自动放行；命令和外部操作由独立审核请求判断，审核上下文只含明确标记的用户任务、准确操作及权限事实，不加载工作流技能。潜在高风险和不确定情况请求人批准；审核异常不执行。审核用量单独计数。目录外访问不因“自动”二字静默放开，需通过明确选择的读取/写入范围；完整模式才放开这些范围。
3. 高风险例子：不可恢复删除、清理/重写 Git 历史、强推、发布/部署、持久修改安全设置、向外传送私有内容、提取凭据。命令名称白名单不能单独证明安全。MCP 的只读注解仅作线索。
4. 完整模式的文件操作、命令和显式 MCP 都跳过逐项批准；命令确实不经沙箱执行，保留超时、输出界限和进程组取消。完整模式的风险必须在选择界面和状态栏清楚显示；不承诺该模式能保护宿主凭据。资源发现仍是显式选择。
5. 搜索复用 OMP 原生 glob/grep：正则、字面匹配选择、路径 glob、gitignore、分页和明确的不完整标记。禁止先读凭据再过滤结果。覆盖超过旧 500 文件位置的命中、无权限文件、符号链接逃逸、取消和无效正则。
6. 修改快照与研究来源不因累计 100/200 条停止工作。复用 Bun 内置 SQLite，正文/快照按需查询并按内容去重，元数据列表有界；现有 JSON 事务迁移，原文件保留，旧来源 ID 和撤销语义不丢失。最新一次运行超过列表页大小时 `/undo` 仍选全。暂不自动删除证据，显示存储统计以便用户判断磁盘占用。
7. 开发环境只从用户选择的环境变量名称读取值；配置不保存真实值。支持明确工具链读取目录、联网域名和每次命令单独申请 Git 写权限，不把任意命令因出现 git 字样认作安全。非完整模式继续保护应用状态和凭据，Git hooks 不自动触发为可信代码。
8. 研究新增按来源位置/PDF 页码继续读取和来源内检索。抓取状态、返回给模型的范围、原文/提取截断分别记录。重复来源可去重，不得覆盖已引用版本或复用已发出的 ID。正文超过 12,000 字符能续读；PDF 页码有效性和解析上限明确。

## 边界、验证与回滚

- 产品包优先；沿用 Bun >=1.3.14、OMP 18.10.3、macOS arm64。无新增依赖，无真实模型/搜索凭据或付费调用，不自动提交、推送。
- 独立审核参考 [Codex Auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)，不宣称达到相同安全水平；它会产生额外模型请求，判断可能出错。
- 测试先证明旧行为失败，再实现；使用真实临时文件、Bun SQLite、本地 HTTP 模型和系统沙箱。运行产品静态检查、产品回归、必要底座检查及真实沙箱组。
- 原始 JSON 保留，迁移失败不清空原件。功能回退可从检查点 a0a22722a4 对照恢复；不丢弃用户工作。完整模式不作为解决沙箱测试失败的办法。
