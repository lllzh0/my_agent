# 第一阶段基础功能同步与补齐

用户已批准上一轮比较中列为必要的功能；本轮明确要求 `main` 保持单 agent，协作功能留在 `codex/team-efficiency`。不包含工作流预设、资源组合切换、GUI，以及按需增强表中的 LSP、OCR、Office、浏览器、结构化 CLI、并行写入或会话分叉。

## 目标与顺序

1. 从冻结的当前源码抽取已完成的授权、搜索、长资料、恢复、goal/BTW 等基础功能同步到本地 `main`，不带产品协作工具或协作状态库。
2. 两个分支共同获得模型管理、会话内新建、项目差异、只读代码审查、MCP 正文进入研究来源的接口。
3. 协作分支额外支持角色/实例选模与思考强度、工作组共享预算和耗时统计。

同步需要本地提交，用户已授权分支同步；不推送、不改写已有历史、不丢弃当前源码。已有 113 个变更文件冻结保存在父工作区 artifacts/phase1-before-sync；不把该副本或真实会话加入提交。无真实模型、搜索或远程 MCP 请求，无个人配置修改。

## 设计与边界

### 模型管理

保持现有 `model` 配置兼容，增加显式 `models` 候选。内置模型复用 OMP ModelRegistry，自定义模型要求明确 API、地址、上下文/输出限制和输入能力，复用原生注册与模型构建。只读当前显式配置，不重新启用全局配置、OAuth 或目录自动发现。

`/model` 列出候选；`/model provider/id` 选择，忙碌或目标正在执行时拒绝。失败保留原模型；成功保留聊天和产品记录、清除临时授权，并同步审核器、工具视图和后续子实例。不同服务或同服务不同连接的凭据不能因并发相互覆盖。模型选择仅本会话生效。

### 新会话

`/new` 复用原生会话生命周期，由 ProductSessions 统一协调。旧聊天、任务、来源和撤销记录保留；新记录使用新 ID，清空审核任务与临时授权，full 不继承。当前模型连接与计划模式维持。运行、排队消息、后台工作或协作未结束时拒绝。取消/提交前失败保留旧会话；原生已提交后的 UI 错误仍须完成产品接线。

### 差异与审查

`/diff` 查看已暂存、未暂存和未跟踪文件；`/diff <base>` 查看与本地基准的差异。复用 `@oh-my-pi/pi-natives/vcs`、OMP review 差异解析和现有显示组件。每个路径仍经过产品读取检查，不将敏感文件、产品状态或工作区外内容装入差异；明确二进制、截断及未检查范围。只读，不自动还原、提交或改文件。

`/review [base]` 收集同一份冻结差异，再通过现有原生子会话执行层启动一个受控只读审查。单 agent 的含义是没有开放式团队/再委派；一次有边界的审查请求不提供 team 工具。输出问题位置、影响、依据和覆盖限制；命令不自动修复。审查会计入本地用量，并支持取消。所有模型提示保存在静态 Markdown。

### 研究来源导入

只接受宿主实际收到并保存的成功 MCP 结果；调用失败、取消、错误结果不成为证据。工具返回一个稳定结果 ID，模型可指定该 ID 导入正文，不能直接提交任意正文或伪造来源地址。保存服务、工具、获取时间、内容摘要和实际文本，注明来自外部工具、是否截断及来源真实性未独立验证。搜索摘要与已读正文必须区分，导入时限定为明确内容获取；来源 ID 可继续用于 read_source/search_source/write_report，跨重启仍有效。复用现有 SQLite 来源存储、取消和大小限制。

### 协作选模与共享预算

默认继承主模型；可对角色（含 decider）指定候选模型和思考强度，也可在实例创建时覆盖。保持子实例只读、独立裁决空白上下文、原有争议限制与权限边界。显式指定无效模型或缺少凭据时报告错误，不静默替换。

保留每实例硬上限，新增工作组共享请求、token 和运行时间限制；统计包括根任务、成员及裁决，并分别显示。请求在发出前预留，防并发突破；token 按服务返回用量累计，不能声称服务端硬费用上限。额度达到后禁止新增探索，收集已有输出并告知根模型未完成范围。保存请求数、token、估算费用和耗时，重启不自动执行旧工作。

## 验收

- main 的真实模拟请求不含任何 team_* 工具，仍能权限切换、原生搜索、恢复、goal 和 BTW。
- 新旧模型实际请求命中各自显式端点和请求头，切换失败保留旧连接；审核请求和子实例同步且凭据无交叉。
- /new 后旧会话可恢复，新任务/来源/撤销为空，full 和临时授权不继承；忙碌/失败不分裂状态。
- Git 临时仓库覆盖暂存、未暂存、新文件、删除、二进制、敏感路径及基准分支；/diff 不调用模型，/review 不改文件。
- 真实本地 MCP fixture 返回正文后可导入、续读、引用；搜索摘要、伪造 ID、错误/取消和超限被明确处理。
- 并发模型 fixture 验证工作组请求不超限、角色选模正确、用量与结果在恢复后可查。
- 产品 check（oxlint/oxfmt/tsgo）、全产品测试、受影响的 OMP 测试，以及独立审查；真实服务表现与人工验收单独标记。
