# 临时工具授权设计

用户已在对话批准：临时启用工具提供单次、当前 Agent 运行两种期限；目录、联网、计划模式继续按原规则检查。2026-10-29 的本轮授权包括实现和验证，不包括提交或推送。

## 目标和边界

预设未选择的产品工具可以人工临时启用，无需编辑预设或切换 Agent。复用现有工具、审批展示、参数验证和模型请求前工具同步。参考 omp `1b727a9fcc3e7b9ad87f6a8d5098df15bebea376` 的 once/session 决策与按工具限定范围；不引入上游的持久目录授权缓存或依赖升级。

只开放现有产品工具目录。`goal` 生命周期管理、授权入口本身、原生工具、未配置 MCP 服务不能通过临时申请扩展。技能不是权限，不自动添加技能。轻量模式保持无工具。

## 入口和执行

新增产品控制工具 `request_tool`，默认在普通运行中可见，不改变预设定义及其摘要。它可列出可申请工具和参数结构，或提交具体工具名、参数对象与理由。模型不能通过参数选择批准结果或授权期限。

`request_tool` 使用现有参数验证器检查并复制参数，人工审批展示的是此次真实调用。结果为 once/run/deny；关闭界面、无交互界面、取消均拒绝。自动审批模式和完整权限模式均不能替人批准新的工具能力。

once 只执行提交的那一次调用，不产生可被其它并发请求消费的通用凭证；仍由原产品工具执行路径完成目录、联网、计划、命令隔离、操作审批和文件记录。run 在当前 Host 内存中记录工具名，后续模型请求可直接看到并使用该工具。无论 once/run，都不自动跳过具体操作审批。

审批前后检查取消信号、工具授权版本、策略版本，旧审批不能在模式变更、撤销或关闭后生效。参数在等待人工审批时不能被外部修改。错误不自动重试，once 再次调用需重新申请。

## 生命周期与管理

run 跨当前进程内同一预设的 `/new` 和 `/resume` 保留；退出、冷恢复、重启、预设切换均清空。临时信息不写入 config/preset/manifest 的资源签名；审计只记录脱敏元数据，不存执行凭证。

`/tools` 展示直观清单：预设启用、临时启用、关闭；支持人工启用到本次运行结束、撤销一个或全部运行期授权。单次仅在有具体调用的申请中提供。模型来源的管理命令必须被拦截。原有 `/resources` 持久开关功能保留，预设仍保持冻结。

一次性 bash 产生后台任务时，保留仅限该任务 ID 的 job_output/job_stop 能力；不开放其它任务或新命令。同一进程切换对话会关闭旧任务并丢弃这些任务凭证。撤销 bash 不妨碍收尾已创建任务。
