## 1. 要交付什么

让用户用一个预设名称选择本次 agent 的工作方式，不必反复改底层配置：

- 工作流 A 只加载 A 选择的指令、技能、工具和 MCP。
- 工作流 B 可以使用另一份 AGENTS.md，也可以不加载任何工作流指令。
- 简单聊天不加载 AGENTS.md、技能、MCP 或文件/命令工具；需要通用工具但不需要工作流指令时，也有空白工具预设。
- 随时能看到“当前实际加载了什么”，而不是只看到某份配置文件写了什么。
- 切换预设进入独立会话；回到旧预设时，可恢复它自己的会话。

**本轮用户已确认：**

1. 切换预设默认进入独立会话，保留当前聊天直接切换的情况以后再考虑。
2. 第一版先管理 MCP 和技能，可信的本地 OMP 代码扩展以后再做。

已有产品仍面向有一定编程基础的 TUI 使用者。提供可直接使用的菜单和命令，也允许编辑 JSON；不把 GUI、配置向导或插件市场加入本阶段。

## 3. 方案选择与已有开源实现

| 方案 | 优点 | 不足 | 决定 |
| --- | --- | --- | --- |
| 每个预设复制一整套 `--home` | 最快接通，目录隔离明确 | 模型和 MCP 配置重复维护，复用资源和统一会话列表不方便 | 保留现有 `--home`，不把它作为预设主方案 |
| 当前会话直接替换工具和提示词 | 切换快，执行层改动较少 | 旧聊天已含指令和技能内容；工具、授权及连接的切换易出现部分生效 | 本阶段不采用 |
| 命名清单解析成运行配置，切换时重建会话执行环境 | 清单明确，共用资源，能隔离聊天与运行状态 | 需要处理进程交接和失败恢复 | **推荐方案** |

参考来源核对于 2026-10-20，仅用于设计，未安装或复制其代码：

- [pi-loadout](https://github.com/tianrendong/pi-loadout)：借鉴按来源勾选、保存清单、显示当前选择的交互。其文档说明技能过滤主要隐藏模型可见列表，手动调用仍可用，且可在当前会话即时应用；这与本产品本阶段的独立会话约定不同，不能整包替代资源隔离。
- [sovorn-c/pi-profile](https://github.com/sovorn-c/pi-profile)：借鉴在进程启动前选择配置目录、预设拥有独立状态的思路。其文档明确预设不是文件系统沙箱，进程内不能直接更换 profile。本产品保留现有模型连接和产品授权层，不复制整套配置目录。
- 本地 OMP 的 `packages/utils/src/dirs.ts`、`cli/profile-bootstrap.ts` 及 `test/discovery/profile-isolation.test.ts`：复用现成的名称校验和启动前目录选择原则；不启用原生全局/项目自动发现。名称校验如因导入依赖过重而不适合极早启动，放到准备子进程中完成，不复制一份近似规则。

这里的“资源隔离”指不会自动加载或启用无关资源，不是让本机文件对模型绝对不可读。用户明确要求读取某个路径，仍按现有工具权限处理；完整授权也不等于自动把所有技能装进提示词。

## 4. 用户实际怎么用

以下是拟新增的接口，目前不能执行：

```text
bun run agent --preset work
bun run agent preset list
bun run agent preset show work
bun run agent preset check work
bun run agent preset create work --template coding
bun run agent preset create research --template research
bun run agent preset bind work
bun run agent preset default work
bun run agent preset unbind
```

`bind` 只把当前工作区的默认预设记在产品自己的配置目录，不往仓库写指令文件。全局默认与工作区默认都仅影响后续启动，不改变正在运行的会话。

TUI 入口：

| 命令 | 行为 |
| --- | --- |
| `/preset` | 打开选择器，显示当前预设、可用预设、缺失资源和已有会话 |
| `/preset use work` | 切到 work；有历史时选择“新建”或某条历史，无历史时直接新建 |
| `/preset use work --new` | 直接进入 work 的新会话 |
| `/preset show` | 显示当前真正生效的资源、工具、模型候选和 MCP |
| `/preset show work` | 预览 work 当前定义；明确标为“切换后生效” |
| `/preset create work` | 从空白或模板新建，名称冲突时不覆盖 |
| `/preset edit work` | 编辑草稿、预览差异、保存；取消不改文件，不影响当前运行 |
| `/preset clone work work-lite` | 复制定义，继续引用原来的资源，不复制聊天或授权 |

工具和技能按来源分组，可搜索和勾选。指令可以添加指定文件，也可以清空。选一个技能目录时先展示扫描结果，保存为用户选中的具体 `SKILL.md` 清单，避免以后往目录加技能就悄悄进入已有预设。

不自动扫描整个用户目录。候选来自已有显式配置、当前预设和用户主动选择的文件/目录。浏览候选不会把未选择的正文发送给模型。

内置两种不可修改但可克隆的预设：

- `chat`：纯聊天，无工作流指令、技能和工具，沿用现有 light 方式。
- `bare`：有常用产品工具，无工作流指令、技能及 MCP。适合临时处理文件而不带主工作流规则。

另有兼容入口 `legacy`，对应现有 config.json 的行为。`coding`、`research` 是新建时的模板，不自作主张选择本机 AGENTS.md、技能或外部 MCP。

第一版 bare 的明确工具集合为 `read`、`ls`、`grep`、`find`、`write`、`edit`、`bash`、`job_output`、`job_stop`、`web_search`、`web_fetch`、`read_document`、`read_source`、`search_source`、`write_report`、`task_list`、`task_update`、`ask_user`、`goal`；不包含 MCP 或团队工具。coding 模板以此为初始集合。research 模板采用下文样例的工具集合，但 MCP 服务初始为空，对应三项 MCP 工具也不选；用户选择服务时再明确加入。模型默认值取创建时已配置的默认连接，候选初始只有该连接。网络工具未配置凭据时沿用现有可操作报错。

chat 必须同时满足资源、工具及 MCP 清单为空；不能用 `mode: "chat"` 搭配非空清单而静默忽略。内置模板的清单由产品明确维护，用户保存的清单不会因以后新增工具而自动扩大。

`--light` 保留：普通新启动等价于选择 chat；与显式 `--preset` 同时提供时报冲突，避免双重来源。恢复没有预设元数据的旧会话时，仍走原先的 light 校验规则。

## 5. 数据与加载规则

### 5.1 文件布局

```text
<MY_AGENT_HOME>/
  config.json                         # 已有连接/服务配置，保留旧格式
  presets/
    index.json                        # 全局默认 ID，version=1
    work/
      preset.json                     # 预设定义
      assets/                         # 用户主动放入的指令正文，可选
  workspaces/
    <canonical-cwd-digest>/preset.json # 此工作区默认 ID 与规范化 cwd
  sessions/                           # 继续使用原有 OMP JSONL
  state/<sessionId>/manifest.json     # 在原记录上增加预设快照
  omp/presets/<id>/agent/              # 新预设子进程的 SDK 运行目录
```

旧 `omp/agent` 和旧会话路径不迁移、不删除。工作区仍取规范化真实路径；同名预设不串联不同工作区的会话。工作区默认记录需要同时核对摘要和 cwd。

### 5.2 定义样例

以下为设计格式，尚未加入现有配置解析器。模型 key 和 MCP 名称必须已经在 config.json 中配置；示例中的 `exa` 不是自动创建或自动联网。

```json
{
  "version": 1,
  "id": "research",
  "name": "资料研究",
  "mode": "agent",
  "model": {
    "default": "opencode-go/deepseek-v4.1-flash",
    "allowed": ["opencode-go/deepseek-v4.1-flash"]
  },
  "resources": {
    "instructions": [{ "base": "preset", "path": "assets/research.md" }],
    "skills": [{ "base": "absolute", "path": "/path/to/research/SKILL.md" }],
    "appendSystem": []
  },
  "tools": [
    "read", "ls", "grep", "find",
    "web_search", "web_fetch", "read_document",
    "read_source", "search_source", "write_report",
    "mcp_list", "mcp_call", "import_mcp_source",
    "task_list", "task_update", "ask_user"
  ],
  "mcpServers": ["exa"],
  "permissions": {
    "approval": "auto",
    "allowNetwork": true,
    "readRoots": [],
    "writeRoots": []
  }
}
```

路径只支持三种明确基准：

- `workspace`：相对当前工作区，例如 `AGENTS.md`。
- `preset`：相对该预设目录，便于随预设保存专用指令。
- `absolute`：显式引用本机已有资源。

前两者在规范化及解析符号链接后不得逃出对应根目录；外部路径使用 absolute 明确表达。不得把 `${...}` 或路径值当 shell 求值。指令排序有意义，按清单顺序装入；重复技能名、失效路径、未知工具和未知 MCP 名称均阻止启用并给出具体位置。

现有 Policy 会保护整个产品 home，直接工具不能读取其中的会话或配置。第一版保持这一规则：preset/assets 只保存由宿主显式注入的指令；需要模型按需读取的技能使用工作区或产品 home 之外的绝对路径。预检查到技能位于受保护目录时，直接说明不能读取并让用户改选外部路径，不能启动后才让模型碰到拒绝。完整技能包导入属于后续可移植功能，不为它提前放宽整个应用目录。

预设 ID 与目录名一致，创建后稳定不变，`legacy`、`chat`、`bare` 保留给内置入口。显示名称可编辑；需要换 ID 时克隆，旧会话继续归原 ID。第一版不做带历史迁移的重命名或删除。

模型、MCP 凭据仍通过既有环境变量引用读取，不复制真实密钥到预设、会话快照或导出文件。预设的 allowed 模型列表限制本会话 `/model` 候选；默认模型必须在候选内。

`permissions` 沿用产品语义。预设可保存 manual/auto、网络与目录范围，**不能保存 full**；full 仍由用户在当前会话显式选择。沙箱规则、命令环境变量名及搜索配置复用当前产品配置并纳入启动快照；不另建一套审核器。

tools 是模型可调用的工具清单，不是对任意 shell 程序的权限证明。保留 bash 时，命令仍有自身能力和授权检查。选择器可以用“文件读取”“命令”“研究”等分组方便操作，但落盘保存具体名称。

工具依赖做显式校验，例如技能需要 read；bash 需要相应后台查看/停止工具；MCP 选择需要 mcp_list/mcp_call。UI 可提出连同依赖一起选择，不能在后台偷偷加回工具。原生 goal 的隐藏工具也必须受预设能力约束，不能通过暂停/恢复把禁用的工具带回来。

### 5.3 没有隐式叠加

新预设里的空数组就是“不加载”。不会把全局资源、祖先 AGENTS.md 或另一个预设的清单合并进来。没有 `extends`、通配继承、自动猜测工作流或每轮动态选预设。

共享的是已安装的文件以及已配置的连接定义，不是自动启用状态。未选中的 MCP 不出现在该会话的服务管理器中，不能通过猜服务名调用；启动、预览和预设检查都不连接远端。

核心产品提示词和安全约束保留，不属于用户 AGENTS.md。`appendSystem` 只能追加；旧 `resources.systemPrompt` 目前也是追加语义，兼容迁移时保持原有顺序，不把它变成替换产品提示词的入口。

## 6. 会话与切换

### 6.1 选择优先级

新建会话：显式 `--preset` → 当前工作区绑定 → 全局默认 → legacy。

恢复会话：先读该会话的预设身份和冻结配置。默认预设不能覆盖恢复目标；若同时指定不同的 `--preset`，报错并说明会话实际所属预设。旧记录没有预设字段时只走 legacy 兼容路径。

`/resume` 继续显示当前工作区历史，但增加预设标签。选中当前预设的兼容会话仍可复用原有原生切换；选中另一个预设的历史时进入同一个预设交接流程，不走旁路。

切换器不直接挑“最近一条”偷偷接着工作；存在历史时由用户选新建还是恢复。恢复不发送模型请求，不继续旧 goal 或后台操作。

### 6.2 保存的是生效快照

新会话记录增加 `presetVersion`、`presetId`、定义摘要和解析后的配置；保存选中资源的路径/内容摘要、工具能力及所选 MCP 连接定义。凭据只保存引用。

- 显示名称变化或未选资源的变化，不应阻止恢复。
- 预设定义改了，新会话用新版，旧会话仍按自己的快照校验。
- 旧会话引用的指令、技能或 MCP 连接定义变了，不静默替换。显示差异，可恢复原资源后继续，或按当前预设新建会话。
- 第一版不保存一整份技能依赖树，不承诺把外部资源还原成旧版。文件缺失或变更是可解释的恢复限制。
- 当前会话 `/model` 与 `/effort` 的选择属于该会话。新格式要保存其成功切换后的连接 key 和强度，恢复 B 时不带入 A 的临时选择；不复制密钥值。
- 新预设采用版本化的生效签名；旧 manifest 保持原签名算法，不能用新规则放宽旧会话校验。
- 任务、来源、撤销记录和旁问历史继续由 sessionId 管理，不新增第二套聊天数据库。

签名包括模式、选中指令的有序内容摘要、选中技能的身份/摘要、明确工具集合及 schema 版本、选中模型连接定义、MCP 定义和有效权限配置；不包括显示名、无关候选、状态栏偏好、临时授权或真实密钥。资源路径排序与有意义的指令顺序不能混为一谈。快照本身保留模型连接字段，但每次恢复都重新读取凭据引用，凭据轮换不会把密钥写回历史。

同预设 `/resume` 沿用原生会话切换，但新格式目标的模型选择要一起协调恢复；如果目标连接已不可用，切换前失败，原会话不变。legacy 继续保留原有“进程内恢复保留当前模型、跨进程按启动配置”的行为，不批量改写旧记录。

### 6.3 重建会话子进程，而不是修改一半运行环境

用户仍留在同一个终端窗口。launcher 保留为启动器，接收本机受控消息，切换会话子进程。复用 Bun 的进程能力；不加网络控制服务，不通过拼接 shell 命令切换。

流程：

```text
用户选择预设/旧会话
    → 检查当前是否空闲、冻结新输入
    → 解析目标并在不占终端的子进程中准备
    → 准备失败：清理目标，继续原会话
    → 准备成功：保存原会话，关闭其 MCP/运行记录并释放终端
    → 确认原会话关闭成功，再激活目标终端
    → 激活失败：关闭目标，尝试从已保存记录重新打开原会话
```

准备进程可以读取选中配置、构造 SDK 和申请目标会话独占，但不得请求模型、执行命令或连接 MCP；就绪后等待启动器激活。准备和清理均有超时、取消及回收逻辑。新会话中途放弃时只清理此次创建且未激活的记录，不能删除已有恢复目标。

启动器只接受当前子进程发出的结构化切换请求，校验会话身份、请求 ID、目标预设和路径；不信任聊天内容或终端输出充当控制消息。提示词不能触发用户专用的预设创建、编辑或切换入口。

忙碌状态沿用并汇总现有保护：模型回答、排队输入、整理上下文、BTW、review、goal、后台任务、授权弹窗、会话/模型切换，以及协作分支仍在运行或清理的成员。先说明哪个任务阻止切换，由用户停止或等待；不为了切换自动杀掉工作。

临时授权和 full 不传给目标。只读计划模式沿用现有新建/恢复规则，不能因预设切换静默解除。原会话已关闭后若回退，需要重新建立运行环境，不能恢复旧 full 或一次性许可；两边记录仍保留，回退失败时打印可恢复的命令。

`/new` 始终在当前预设的新会话中执行，不重新套用已改变的全局默认。`/preset use 当前ID` 在定义未变且没有 `--new` 时提示“已在此预设”，不会重开；若磁盘定义改变，则展示差异并新建，不能把新定义装进已有聊天。

这不是跨进程磁盘事务。目标准备前失败、原会话清理失败、目标激活后失败分别处理，不承诺“任何异常都完全无感”。任一时刻只能有一个会话接收终端输入。

## 7. 可见性与配置编辑

状态栏显示预设名和已选指令/技能/MCP 数量，现有 TPS/首字等待统计继续使用原生显示。

`/preset show` 至少提供：

- 当前预设与会话 ID、工作区、当前模型和候选。
- 已加载指令的路径、顺序及字节数。
- 已广告的技能与已经读取正文的技能，分清这两种状态。
- 实际可调用工具，选中的 MCP 及其连接状态。
- 没有加载工作流指令时明确显示“未加载工作流指令”。
- 当前运行快照与磁盘新定义是否不同。

不通过额外模型调用生成预设说明。第一版显示准确的文件数量和字节数；有合适的原生 token 估算器再显示“估算”，不能把字符数当真实 token 或承诺固定节省比例。

编辑器持有独立草稿。保存前校验并展示增删差异，以现有原子写入方法落盘，取消不产生修改。保存正在使用的预设时，当前运行快照保持原样，用户可以选择稍后切换或现在新建。

两次编辑并发时比较打开时的文件摘要，发现外部改动就拒绝覆盖并提示重新加载。旧 `/agent` 的资源修改菜单必须转到对应预设草稿，不能同时继续改全局 config 并造成两套相互冲突的入口。

## 8. 两分支落地方式

共享能力从 main 的保存点另开功能分支实现；main 的单 agent 定位不变。协作分支只在共享提交验证后同步，不把协作实现带进 main。

共享预设格式允许可选的 `collaboration: { "mode": "off" | "auto" }`：

- 新建的通用预设默认 off。
- main 只接受 off；收到 auto 时提示需要协作版本，不静默忽略。
- 协作分支提供薄适配，复用已有角色选模和预算配置，不在本阶段设计新的角色流程。
- 原 legacy 模式保持该分支原有配置行为。
- 所有子实例的资源和工具受当前预设及角色限制的交集约束；独立决策者继续使用既定空白上下文，不注入完整工作流提示。
- chat/bare 等预设的切换不能保留旧工作组、未读协作消息或目标续跑。

协作真实效率验收继续独立进行。它不成为 main 预设功能开工的前置条件，但协作分支声称支持预设前，必须有其单独的隔离与切换自动回归。

## 9. 分批实现、优先级与验收

这是一份实现设计和批次划分；尚不是已批准执行的逐测试开发计划。完整设计确认后，再用 writing-plans 技能把下一批拆成具体测试和代码步骤。

| 批次 | 优先级 | 应完成的事 | 为什么先做 | 验收结果 |
| --- | --- | --- | --- | --- |
| 2A：定义与启动 | P0 | 清单校验、路径解析、连接引用、生效配置编译、`--preset`、legacy/chat/bare、版本化会话记录 | 先证明真的只加载所选资源 | 本机假模型实际请求中 A/B 指令、技能和工具互不混入，旧入口可恢复 |
| 2B：选择与编辑 | P0 | `/preset` 菜单、创建/克隆/草稿编辑、show/check、全局与工作区默认、状态栏 | 用户不用反复手工改大配置 | 所有日常选择可由菜单完成；取消/编辑冲突不覆盖文件；没有额外模型请求 |
| 2C：终端内切换 | P0 | 启动器交接、统一 resume 路由、空闲门禁、保存/准备/激活/回退 | 满足快捷切换且保持会话独立 | A→B→A 恢复正确；故障不会把 A 的记录和 B 的工具拼在一起 |
| 2D：跨分支适配与交付 | P0 | main 全回归后同步协作适配、升级说明、使用示例及实际终端验收 | 防止两个版本功能分叉或宣称超出证据 | main 无团队工具；协作按预设收紧；所有现有第一阶段回归保留 |
| 可移植导入导出 | P2，后续 | 路径重映射、资源打包、冲突与缺失依赖处理 | 本机明确路径已经满足第一版；跨机器包另有兼容成本 | 不作为本阶段完成门槛 |

### 必须守住的测试场景

1. 在全局、祖先目录、项目和未选技能中放唯一标记，只选择 A；检查实际发给假模型的系统内容、工具定义和技能列表，确认未选内容没有被自动注入。
2. chat 发出的实际请求无工作流指令与工具；bare 有所选工具、无工作流资源。不能靠“模型看起来没有提到某技能”判断隔离成功。
3. MCP A/B 使用本机 fixture：未选服务无连接、无可调用入口；猜名调用失败；预览和 check 不连接服务。
4. 切换 B 后没有 A 的聊天、任务、来源、撤销、BTW 或授权；回到 A 恢复自己的记录，模型连接不串用。
5. 资源修改、预设显示名改变、默认改变、未选连接新增、凭据轮换分别覆盖：该阻止的明确阻止，不相关改变不误拦截；原有旧签名分支继续验证。
6. 目标准备失败、目标被占用、原会话清理失败、目标激活失败、进程退出/信号和重复切换请求分别验证恢复路径；保留原会话及已有目标。
7. streaming、goal、BTW、review、授权等待、排队输入、后台进程及协作清理时禁止切换；空闲后可切换。
8. 禁用的工具不能被 goal、resume、原生命令或协作成员重新加入；选择中的技能正文仍按需加载。
9. 更新正在使用的预设不会改变当前运行；同一文件被另一个编辑器改过时拒绝覆盖。缺失文件不能被默认为“空预设成功”。
10. main 与协作分支各跑产品 check 和全套产品回归；底座若有变更再跑对应原生回归。真实 PTY 覆盖选预设、新建、切换、恢复、退出与错误提示；真实模型任务质量单列，不与离线隔离测试混算。

## 10. 风险、回退与完成边界

- 最大技术风险是终端与子进程的交接，2A/2B 可独立使用命令启动；2C 不通过故障回归就不宣称支持运行中快捷切换。
- 旧会话兼容是硬要求。新字段只增加在新记录上，保留 legacy 解析；不批量改写旧聊天、个人配置或资源文件。
- 用户内容路径变化会影响恢复。show/check 必须明确指出具体资源，不能偷偷寻找同名替代项。
- 预设降低误加载和上下文干扰，不能保证模型永不误判，也不把它描述为新的系统安全沙箱。
- 功能回退通过回到两个已保存的第一阶段提交或创建后续修复提交完成；不通过删除会话、覆盖用户配置或改写已发布历史实现。

**第二阶段完成标准：** 用户能创建两个不同资源组合并快捷切换；可以明确选择不加载工作流指令；未选资源不被自动装入；会话恢复与错误回退有证据；main 保持单 agent；文档列明实际支持范围。上述场景完成后不再继续把代码扩展、预设继承、自动路由、旧聊天搬运、远程市场和 GUI 塞进第二阶段。
