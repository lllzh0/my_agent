# OMP 命令全表与本产品的接入建议

日期：2026-10-15。依据本地 OMP 18.10.3 fork，基线提交 `7414b7c919` 及当前未提交的产品包装代码；不是在线最新版清单。本轮只盘点源码、核对注册表并输出建议，没有开放命令或改动运行逻辑。

这里的“实现”优先指复用或适配 OMP 已有能力。文件工具、模型通信、会话存储和界面组件已有底座，不应重新写一套。需要适配的是：功能是否只操作当前产品允许的资源、权限、工作区，以及产品自己的任务、来源和修改记录。

清单覆盖 **85 个内置斜杠命令、8 个别名、4 个随包提供的额外命令、53 个终端注册入口**。终端入口包含默认启动入口 `launch` 和隐藏补全入口 `__complete`。技能、插件和提示词模板动态生成的命令没有固定总数，单独说明。`read`、`bash` 等模型工具不作为用户命令重复计数。

**建议规则**

| 标记 | 含义 |
|---|---|
| 保留 | 当前已接入，或已有产品等价能力，继续复用 |
| 一阶段补充 | 优先补的基本操作或可靠性入口；是本次建议，不自动改写已经确认的验收条件 |
| 二阶段 | 与工作流预设、资源启停和指令加载直接相关 |
| 三阶段按需 | 日常体验或能力增强，使用后再决定是否接入 |
| 不纳入核心 | 当前产品方向无需做成基础功能；可保留在 OMP 开发工具或以后专门的扩展中 |

**当前产品实际开放的范围**

聊天入口明确放行 `/agent`、`/agent-plan`、`/quit`、`/q`、`/compact`、`/session`、`/hotkeys` 和已选择的 `/skill:<名称>`。其中 `/agent` 已提供资源、权限、MCP 外部工具、来源、后台任务、文件恢复及任务进度菜单。原生命令有实现，并不代表当前产品入口已经接通。

终端入口为 `bun run agent`，已有产品自己的 `setup`、`doctor`、`diagnose`、`restore-config`，以及 `--home`、`--cwd`、`--resume`、`--light`、`--demo`、`--print --prompt`。这些不是全部 OMP 子命令的透传。

## 1. 斜杠命令：基本操作、状态和排障

| 命令 | OMP 中的作用 | 建议 | 当前关系与理由 |
|---|---|---|---|
| `/plan` | 进入或退出原生计划模式，可附带要规划的任务 | 保留等价能力 | 已有 `/agent-plan` 的只读计划限制；如增加同名入口，应调用产品模式，避免出现两套计划状态 |
| `/plan-review` | 重新打开最近一份原生计划的审阅界面 | 三阶段按需 | 当前产品只有只读模式，没有原生计划审阅流程；不能只加入口就称为已接入 |
| `/compact` | 手动压缩会话，支持不同压缩方式和关注点 | 保留 | 已放行；长时间编程与研究都需要；压缩后仍须保留任务、来源和操作证据 |
| `/context` | 查看估算的上下文占用及组成 | 一阶段补充 | 直接回应减少无关指令、技能和 token 的目标；应同时显示当前选择的资源及估算限制 |
| `/tools` | 查看 agent 当前可见的工具 | 一阶段补充 | `/agent` 已有等价清单；增加快捷入口即可，显示产品包装后的工具 |
| `/effort` | 查看或调整当前会话的思考档位 | 一阶段补命令入口 | 原生 Shift+Tab 调档没有被产品禁用，底层能力已有；按模型支持的档位提供选择，不承诺关思考能解决停顿 |
| `/retry` | 重新调度最后失败的一轮 | 一阶段补命令入口 | 原生 F5/Alt+R 重试没有被产品禁用；复用已有续接逻辑，保留已经完成的工具结果，不能无条件重跑整项任务 |
| `/fresh` | 重置客户端维护的供应商续接状态，保留本地聊天记录 | 一阶段补充 | 可以作为排障操作；不是新建会话、清空上下文或自动重试，也不保证修复服务端异常 |
| `/usage` | 查询供应商使用量、额度等信息，部分服务还支持消耗已存的额度重置机会 | 一阶段补充基础显示 | 先显示本会话 token 和可获得的费用信息；账户额度按服务能力支持，不接入消耗额度重置机会的操作 |
| `/session` | 查看会话信息；另有 `info`、`delete`、`pin` 子操作 | 保留信息查看 | 已放行根命令；产品只读信息与删除、OAuth 账户绑定应分别评估，不能把根命令放行等同于全部子操作已适配 |
| `/todo` | 查看、清空或追加原生待办列表，按阶段组织任务 | 保留等价能力 | 已有产品 Workflow 任务记录；快捷入口应接到该记录，保留完成任务需要证据的约束 |
| `/jobs` | 查看异步后台工作，查看完整输出或终止任务 | 保留等价能力 | 已有受控后台进程和菜单；应接产品 Supervisor，不能只查看另一套原生任务队列 |
| `/mcp` | 添加、列出、移除、测试 MCP 服务，并管理工具、连接与授权等操作 | 保留产品实现；增加同名入口按需 | `/agent` 已有受控 MCP 菜单；入口应调用 ManagedMcp，保留显式连接和具体业务调用批准，不引入原生自动发现 |
| `/hotkeys` | 列出快捷键 | 保留 | 已放行；帮助内容应与产品实际开放的操作一致 |
| `/quit`，`/q` | 正常退出 | 保留 | 已接入产品退出清理，关闭 MCP、后台进程并刷新记录 |
| `/exit` | 退出应用，与 `/quit` 目的相同 | 三阶段按需 | 当前未放行；可加为同一个退出流程的别名，无需单独开发退出能力 |
| `/queue` | 将消息排队，等当前工作交出控制权后处理 | 三阶段按需 | 对长任务有用，但要定义排队消息是否跨模式或预设继续生效 |
| `/force`，`/force:<工具>` | 强制下一轮使用指定工具，可附带任务文本 | 三阶段按需 | 是调试和精确控制入口；只能选择已经开放的产品工具，不能增加工具权限 |
| `/pause` | 暂停原生主 agent、子 agent 和顾问，之后恢复 | 三阶段按需 | 当前单 agent 的取消入口已有；全局暂停需要另行定义受控后台进程是否继续运行 |
| `/debug` | 打开原生调试工具菜单，含响应、终端、系统等诊断入口 | 保留产品诊断；原菜单不纳核心 | 已有 `doctor`、`diagnose` 和异常响应摘要；不必开放包含完整转储、远程调试等内容的整套原生菜单 |

## 2. 斜杠命令：模型、配置、技能和插件

| 命令 | OMP 中的作用 | 建议 | 当前关系与理由 |
|---|---|---|---|
| `/settings` | 打开 OMP 全量设置菜单 | 二阶段做产品自己的设置 | 当前接受配置文件；只展示已接入的字段和预设，原生全量设置会允许打开产品未适配的能力 |
| `/setup`，`/providers` | 配置供应商登录和搜索服务 | 保留简版；完整向导三阶段按需 | 已有产品 `setup`、配置校验和环境变量；完整供应商向导不是当前 TUI 门槛 |
| `/model`，`/models` | 打开模型选择器，并可管理模型角色 | 三阶段按需 | 模型配置能力已有，热切换未接；先支持已配置服务下的模型，再考虑跨服务和角色体系 |
| `/switch` | 临时切换当前会话模型，支持模糊名称、供应商/模型、角色和档位选择 | 三阶段按需 | 适合作为 `/model` 的快捷方式；需要同步实际模型、恢复记录及资源配置检查 |
| `/modelpreset` | 保存、列出、切换或删除模型角色及思考档位组合 | 二阶段吸收 | 可以复用模型配置部分；它不包含技能、AGENTS.md、插件和 MCP，不能直接当作本产品的完整预设 |
| `/skillful` | 开关系统提示词中的可用技能目录，并查看开关状态 | 二阶段适配 | 只控制技能目录展示，不等于卸载技能、禁止读取或清除历史中已加载的内容 |
| `/skills` | 在技能注册站搜索、安装、列出和更新技能 | 二阶段先做选择与启停；下载管理三阶段按需 | 本产品已支持显式本地路径。先区分“已安装”与“当前预设启用”，不必先做技能商店 |
| `/extensions`，`/status` | 打开原生扩展控制中心 | 二阶段替换为产品资源清单 | `/agent` 已有部分等价信息；应同时呈现指令、技能、插件和 MCP 的实际启用状态及来源 |
| `/marketplace` | 添加/移除插件市场、更新目录、浏览、安装、卸载及升级插件 | 不纳入核心 | 完整市场不是工作流隔离的前提；可以先接显式选择的本地包或仓库，避免先承担市场系统维护 |
| `/plugins`，`/plugin` | 查看插件并启用或停用市场插件 | 二阶段适配 | 插件资源控制与产品方向直接相关；安装范围、预设启用范围及代码插件执行能力要分开管理 |
| `/reload-plugins` | 重载插件、技能、命令、钩子、工具、agent 定义和 MCP | 二阶段受控实现 | 不直接执行全量发现和重载；只处理当前预设选择的资源，并明确新会话、重启或历史处理方式 |
| `/login` | 通过浏览器授权登录供应商 | 三阶段按需 | 当前 OpenCode Go 使用环境变量密钥；只有增加需要此类登录的服务时才做 |
| `/logout` | 移除供应商登录授权 | 三阶段按需 | 与正式接入的登录方式一起做；不能假装移除会话中的环境变量密钥就是注销远端账户 |
| `/fast` | 为支持的供应商选择优先或快速服务档位 | 三阶段按需 | 这是服务档位，可能影响价格；不是把模型换成 Flash，也不是降低思考档位；当前 Go 不需单独做入口 |
| `/slow` | 使用支持的灵活服务档位，或在特定供应商限额后以低优先级继续 | 不纳入核心；按供应商增补 | 不等于提高思考档位，也不同于 `--slow` 模型角色；当前服务没有这项明确需求 |
| `/extended-context` | 切换供应商支持的较大上下文窗口 | 三阶段按需 | 只在模型确实支持时提供；长研究任务先使用当前上下文管理与压缩 |

## 3. 斜杠命令：会话和工作区

| 命令 | OMP 中的作用 | 建议 | 当前关系与理由 |
|---|---|---|---|
| `/new` | 创建新会话 | 三阶段按需 | 当前退出后重新启动已能新建；若在进程内实现，需要重建产品附属状态和授权 |
| `/clear` | 保留会话身份，在原会话内清空对话上下文 | 三阶段按需 | 必须定义任务、来源、文件修改记录如何保留；不能用作工作流切换时的简单资源清理替代品 |
| `/delete` | 删除当前会话并创建新会话 | 三阶段按需 | 删除须覆盖产品附属状态并正确释放会话租约；不是第一阶段门槛 |
| `/resume` | 打开选择器并切到另一段会话 | 保留手动恢复；选择器不必实现 | 已有 `--resume`。你已确认手动恢复即可，不为此增加会话浏览界面 |
| `/pin` | 在会话恢复列表中置顶或取消置顶 | 不纳入核心 | 依赖会话选择器；目前没有相应使用需要。与 `/session pin` 的账户绑定不是同一件事 |
| `/rename` | 手动或调用模型为会话命名 | 三阶段按需 | 长期管理较多研究/编程会话时再做；基础实现不必用模型自动起名 |
| `/branch`，`/rewind` | 回到较早的消息位置，旧路径保留成会话分支 | 三阶段按需 | 需要让产品任务、来源、变更记录与新分支同步；回退聊天不自动回退文件 |
| `/fork` | 复制/分叉会话，也能在终端新窗格或窗口打开 | 三阶段按需 | 会话复制有价值，终端窗格整合可不做；不能共享旧授权或混用附属状态 |
| `/tree` | 浏览会话树并切换分支 | 不作为必要功能 | 只有正式支持会话分支后才考虑；不影响目前手动恢复的使用方式 |
| `/handoff` | 生成交接摘要并在原会话压缩 | 三阶段按需 | 适合长任务；用户主动调用的原生路径不会必然保存一份磁盘交接文件，不能误当作预设切换或跨机器迁移 |
| `/shake` | 丢弃上下文中的大块内容、图片或思考块 | 三阶段按需 | 高级上下文操作；要保留研究来源和必要推理协议，默认仍使用压缩 |
| `/move` | 把当前会话工作目录迁到另一目录 | 不开放原生入口；以后有需求再适配 | 产品工作目录、沙箱、后台进程及恢复记录绑定在一起；当前用新 `--cwd` 启动新会话 |
| `/wt`，`/worktree` | 把当前工作与改动迁入新 Git worktree，即同仓库的独立工作目录 | 三阶段按需 | 可先由用户手动创建 worktree 后以 `--cwd` 启动；会话内迁移需要完整状态适配 |
| `/add-dir` | 给会话增加额外工作目录 | 三阶段按需 | 多仓库工作确有价值；需要同步路径权限、沙箱及恢复配置 |
| `/remove-dir` | 移除额外工作目录 | 三阶段按需 | 与增加目录一起做，撤销旧授权并处理仍在运行的任务 |
| `/dirs` | 列出当前会话工作目录 | 三阶段按需 | 单目录信息已有；真正支持多目录后再提供独立入口 |
| `/restart` | 用原启动参数重启 OMP 并恢复当前会话 | 保留手动方式；三阶段快捷入口 | 产品已有完整恢复命令；自动重启必须进入产品启动器，保留 home、cwd 和资源配置 |

## 4. 斜杠命令：编程、研究与内容操作

| 命令 | OMP 中的作用 | 建议 | 当前关系与理由 |
|---|---|---|---|
| `/git` | 打开差异查看、暂存和提交编辑界面 | 三阶段优先评估 | 编程有用；可先接只读 diff，暂存和提交继续由用户明确操作；不用先做完整 Git 客户端 |
| `/browser` | 切换已经启用的浏览器能力为隐藏或可见模式 | 三阶段优先评估 | 研究登录页面、动态页面时有价值；这条命令本身不提供网页搜索，也不代表浏览器工具已接通 |
| `/computer` | 为当前会话启用桌面操作能力的执行环境 | 不纳入核心 | 桌面自动化是另一种能力；第四阶段做本产品 GUI，不代表必须让 agent 操控整个电脑 |
| `/security` | 规划、运行、查看、取消、导入导出及比较安全扫描 | 不纳入基础核心 | 是专门的安全研究工作流；可在以后相应预设中按需接入，不必随日常 agent 常驻 |
| `/export` | 导出聊天为 HTML | 三阶段按需 | 有利于存档和交流；研究报告及来源链已经有独立能力，不等于聊天导出 |
| `/copy` | 从对话中选择文本或代码并复制 | 三阶段低成本优先 | 同时利于编程与研究，可复用原生选择界面 |
| `/open` | 在浏览器打开对话里的最近链接或选定链接 | 三阶段按需 | 研究有用，但不是浏览器自动化；保留明确的用户触发 |
| `/changelog` | 查看 OMP 更新记录 | 不纳入原生入口 | 产品应该展示自己的版本及改动，不应让用户把底座发布记录当成产品已接入功能 |
| `/stats` | 打开本地用量统计仪表盘 | 三阶段按需 | 先做当前会话用量；整套统计站不是基本能力门槛 |
| `/trace` | 在统计仪表盘打开当前会话的执行过程 | 三阶段按需 | 基础诊断已有；只有需要细看多步骤性能时再接完整可视化追踪 |
| `/memory` | 检查和维护原生长期记忆 | 不默认纳入核心 | 全局记忆可能把主工作流信息带到其他任务；若以后实现，必须有明确的预设范围、查看和删除方式 |

## 5. 斜杠命令：自动运行、多 agent、协作与其他能力

| 命令 | OMP 中的作用 | 建议 | 当前关系与理由 |
|---|---|---|---|
| `/advisor` | 开关第二个模型，让它逐轮审阅并注入建议；可查看、配置或导出其记录 | 不纳入基础核心 | 增加持续模型调用、上下文和调试负担；普通代码审查可显式发起 |
| `/agents` | 管理不同 agent 的模型、模型交接和顾问配置 | 三阶段有子 agent 需求时做 | 先确定基本委派任务能力，再做相应管理；当前包装入口未开放原生子 agent |
| `/hub` | 打开实时 Agent Hub | 不纳入基础核心 | 原生多 agent 管理界面不是单 agent 的必需功能 |
| `/vibe` | 让主会话只读，作为指挥者驱动常驻的快/强工作 agent | 不纳入基础核心 | 这是一套特定的多模型协作模式，不是普通聊天的简化模式 |
| `/goal` | 设置、查看、暂停、恢复、放弃长期目标，并设置 token 预算 | 已复用接入（2026-10-17） | 按用户后续要求启用原生目标模式；补齐受控工具、计划边界和冷恢复审核上下文，见[用法](workflow-agent-goal-btw.md) |
| `/guided-goal` | 让模型先提问，再建立目标模式 | 不必单独实现 | 基础结构化提问已有；先确认目标模式本身有使用需求 |
| `/loop` | 重复提交任务，可按次数、时长或命令退出状态控制继续/结束 | 不纳入基础核心 | 自动重复会引入副作用重放及消耗控制；以后专门任务可用明确的有限循环 |
| `/prewalk` | 按工作进展从初始模型一次性交接到另一个模型，也可重新启用或关闭 | 不纳入基础核心 | 自动换模型会增加理解和排障成本；先使用明确的模型选择或预设 |

| `/live` | 启动由特定模型服务支持的实时语音模式 | 不纳入核心 | 不是当前编程/研究 TUI 的必要能力 |
| `/record` | 开始或停止终端会话画面录制，之后可回放 | 不纳入基础核心 | 可保留为开发演示工具；普通会话记录和诊断已有 |

| `/ssh` | 添加、查看或移除 SSH 远端主机配置 | 不纳入当前核心 | 当前范围是本机工作区；真有远程开发需求后再设计远端权限和文件工具 |

原生通用的 `omp --help` / `omp help`、`omp --version`、`omp --license` 分别显示帮助、版本和许可信息。产品应有自己的帮助和版本信息，许可随交付要求保留。这些是通用入口，不计入上述 53 个注册条目。隐藏 worker 选择器是 OMP 内部进程通信协议，跟随底座保留，不做成产品用户功能。

## 8. 启动参数、快捷输入与容易混淆的功能

53 项 `launch` 帮助参数的原始元数据保存于父工作区 `artifacts/omp-commands/cli-catalog.json`；这里按实际产品选择归并，不把参数重复算成 53 个功能。

| 参数或输入 | 作用 | 对本产品的建议 |
|---|---|---|
| `--model`、`--provider`、`--models`、`--thinking`、`--service-tier`、`--hide-thinking` | 模型选择、轮换范围、思考档位、服务档位和思考展示 | 模型/思考信息应明确；当前配置文件继续可用；服务专有档位按需，展示开关不等于停止模型思考 |
| `--smol`、`--slow`、`--plan`、`--advisor`、`--external-thinking` | 给特定工作角色分配不同模型或启用顾问/外部思考 | 二阶段可把明确需要的角色纳入预设；多模型编排不作为第一阶段门槛 |
| `--prewalk`、`--no-prewalk`、`--prewalk-into`、`--plan-yolo`、`--plan-yolo-into`、`--goal` | 自动模型交接、自动通过计划及持续目标 | 不默认接入；不改变目前只读计划及逐次批准的约束 |
| `--profile`、`--alias` | 隔离一套配置/授权/会话/缓存，或生成相应 shell 别名 | 可参考底层隔离方式；并非完整工作流预设。项目目录和其他工具的全局资源发现仍须单独控制 |
| `--config`、`--system-prompt`、`--system-prompt-template`、`--append-system-prompt` | 附加配置或替换/追加系统提示词 | 二阶段通过产品预设明确选择，显示实际加载清单；当前显式资源加载器继续作为入口 |
| `--extension`、`--hook`、`--no-extensions`、`--skills`、`--no-skills`、`--no-rules` | 选择扩展、技能与规则发现方式 | 二阶段核心配置，但应落到产品资源清单；不要变成一组必须记忆的零散开关 |
| `--tools`、`--no-tools`、`--no-lsp`、`--no-pty` | 调整工具集合、语言服务、终端执行方式 | 保留产品工具限制；后续按预设声明能力，开启原生工具须先适配权限与取消 |
| `--cwd`、`--add-dir`、`--allow-home` | 选择启动目录、额外工作区及主目录启动行为 | `--cwd` 已有；多目录第三阶段按需；主目录默认授权范围不扩大 |
| `--resume`、`--continue`、`--restore`、`--session-dir`、`--no-session` | 手动恢复、续接最近会话、恢复未完成工作、选择存储目录、不保存会话 | 手动 `--resume` 已有且足够；自动恢复未完成操作不能等同于普通恢复，临时无保存模式以后按需 |
| `--from-claude`、`--from-codex` | 导入其他工具的历史会话 | 三阶段有迁移需求时再做；导入聊天不等于恢复原工具的权限、任务或环境 |
| `--print`、`--mode`、`--no-ui`、`--export` | 单次输出、结构化/协议输出及导出 | 产品已有 `--print --prompt`；协议出口由实际集成需要决定 |
| `--no-title`、`--print-thoughts`、`--max-time` | 标题、单次输出是否包含思考、运行时限 | 基础信息与可控取消应保留；思考原文不进入默认诊断，时限可按需要开放 |
| `--api-key`、`--auto-approve`、`--approval-mode` | 直接传密钥，以及改变原生授权策略 | 当前继续用环境变量名；不直接开放绕过产品权限的自动批准开关 |
| `!命令`、`!!命令` | 从输入框直接执行 shell；第二种不把输出放进模型上下文 | 原生入口当前被拦截；若以后接入，必须进入产品沙箱并接好取消/退出，不能仅放开输入解析 |
| 原生 Python / Eval 直达输入 | 直接在持久执行环境运行代码 | 不纳入当前核心；已有受控 shell 足以执行常用开发与研究脚本 |
| `@文件`、粘贴图片或文件 | 给模型提供明确选中的材料 | 适合三阶段优先验证；附件读取与显式加载 AGENTS.md 是不同机制，需要避免隐式扩大范围 |
| `ultrathink` | 该轮要求更深入思考，自动思考时可选到最高支持档位 | 不必做隐藏口令；明确的 `/effort` 和状态展示更好理解 |
| `orchestrate`、`workflowz`、`jevify` | 分别引入并行委派、持久执行环境中的工作流、批量模型判断约定 | 不作为默认产品口令；依赖的任务/执行工具未接入时不能称为可用能力 |

`omp settings` 不是这版注册的独立终端命令；虽然源码中有同名实现文件，实际终端入口是 `omp config`，聊天里则是 `/settings`。同理，`/modelpreset` 不是 AGENTS.md/技能/插件的完整预设，`/browser` 不是联网搜索，`/slow` 不是思考档位，`/pin` 与 `/session pin` 也不相同。

**快捷键和隐藏行为也要核对**

从当前源码看，产品没有禁用原生 Shift+Tab 调档、Ctrl+T 思考开关、F5/Alt+R 重试和后续消息队列键。这证明相关入口仍有源码支持，不是本轮实机按键验证。因此补 `/effort` 和 `/retry` 主要是统一可发现的用户入口，不要重复开发已有引擎功能。

原生魔法词在会话层生成额外指令，并不只受斜杠命令名单控制。产品没有显式关闭该设置；缺少必需工具的多 agent 魔法词会被原生逻辑跳过，但 `ultrathink` 这类无需工具的行为仍应单独核对是否保留。

## 9. 建议采用的推进顺序

第一阶段继续完成真实模型和真实任务验收。命令层建议优先做：与实际可用能力一致的帮助/补全、`/context`、`/effort`、受控 `/retry`、`/fresh`、当前会话用量显示；`/tools`、`/jobs`、`/todo`、`/mcp`、`/plan` 主要是为已有产品能力增加一致的快捷入口。无需为这些入口重新写任务引擎或 MCP 客户端。

第二阶段集中做真正的工作流预设：命名预设、明确的指令/技能/插件/MCP 选择、已安装与当前启用的区分、加载内容与预算预览，以及切换时的聊天历史处理。模型配置可以吸收 `/modelpreset` 的实现；原生 `--profile` 可作为底层隔离参考，但不能替代资源发现控制。更换设置不会自动删除已经进入聊天历史的指令或技能正文。

第三阶段按使用频率评估：模型热切换、复制/打开链接、只读差异与审查、动态网页浏览、会话命名/导出、工作区扩展和必要的子 agent。编程与研究同等重要，因此浏览器与来源操作应和 Git/审查一起排优先级，不把研究能力永远放在最后。

第四阶段把稳定的配置、会话、来源、任务和权限能力接到 GUI。GUI 是展示与交互入口，不是把原生所有命令、语音、直播、桌面自动化和多人协作都作为发布条件。

**2026-10-16 更新：已处理两处命令一致性问题**

1. 产品现从同一份清单生成 `/help`、补全和命令识别；原生 TUI 接受嵌入方提供的可选补全表。测试验证隐藏未接入的原生命令及其参数补全；不传该选项时保持原生行为。
2. `/session` 仅显示信息，拒绝 `delete` 和 `pin`。`/mcp` 调用产品现有菜单，不转交原生 `reload` 等子命令。

手动 `/compact` 现固定使用 `soft` 摘要路径，拒绝 `remote` 和 `snapcompact`；真实模型的压缩效果仍须试用。`/context`、`/effort`、`/retry`（别名 `/redo`）、`/fresh`、本地 `/usage`、`/tools`、`/jobs`、`/todo`、`/mcp`、`/plan` 已补入口。新增 `/undo` 按运行轮次恢复直接文本修改并保留聊天，范围及证据见 [基本命令与撤销](workflow-agent-basic-commands.md)。上面的原生命令清单和分阶段建议保留为盘点记录。
