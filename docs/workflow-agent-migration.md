## 本轮发现并修复的问题

| 触发条件与影响 | 原因与处理 | 验证 |
|---|---|---|
| 显式设置仍读入项目配置 | OMP 的内存设置不会自动关闭项目发现；增加可选发现开关 | 宿主污染夹具及原生设置兼容测试通过 |
| 原生 `models.yml` 影响产品选定模型 | 模型目录默认读本地覆盖；使用现有 `ignoreLocalModelConfig` 选项 | 有效的模型覆盖夹具先复现，再验证未采用污染值 |
| 原生文件选择器改变已检查路径 | 原生读取语法可重新解释目标；产品只接受普通路径，行范围单独传参 | `.env:raw` 无法读出测试凭据；普通范围读取通过 |
| 资源目录为单个技能时未加载 | 目录扫描默认只找子项；显式包含所选目录自身 | 单技能目录、单文件与实际请求检查通过 |
| 自定义工具收到错误的取消参数 | OMP 18.10.3 对未标记工具按旧回调签名转换；使用原生 ToolDefinition 标记 | 实际模型写入、编辑、读取和取消路径通过 |
| 工作区读取规则重新放行凭据/状态 | 沙箱运行时 0.0.50 的规则顺序覆盖较早 deny；在生成配置最后补上保护规则并检查格式 | 实际 OS 测试拒绝嵌套状态目录、凭据读写和 `.omp` 写入 |
| 退出后才启动准备中的命令 | 原实现仅清理已经启动的子进程；关闭状态贯穿异步准备边界 | 回归测试先失败，修复后拒绝启动且没有新增任务 |
| 技能与 `/mcp` 等命令重名 | 将裸技能名加入命令许可表会放行同名原生命令；仅开放 `/skill:名称` | 碰撞夹具先失败，修复后原生命令被拦截、技能形式仍可用 |
| 编辑后文件超限，缺少恢复记录 | 只检查输入片段不能限制合并后大小；复用原生文件写入桥，在落盘前检查最终文本 | 超大编辑与报告测试先失败，修复后原文件不变且无多余记录 |
| 状态栏目录及退出恢复提示指向错误入口 | SDK 缓存启动目录、原生 TUI 生成 `omp` 命令；子进程先切 cwd，并提供产品恢复命令 | PTY 显示指定工作目录；复制退出提示加 `--print --prompt` 后恢复并回答，退出码 0 |

## 为复用 OMP 保留的兼容改动

没有重写 OMP 的模型流、历史存储或终端渲染。本轮对上游主包的源码改动集中在三个文件：

1. `config/settings.ts`：增加可选 `discoverProjectSettings`，默认仍为原生行为；overlay/clone 保留调用方选择。
2. `modes/types.ts`：允许嵌入方传入快捷键和恢复命令。
3. `modes/interactive-mode.ts`：使用显式传入的快捷键及恢复提示；原生调用未传参时维持原行为。

产品包装使用 OMP 已有的工具、文件写入桥、模型目录和会话接口。新包保留原型中已验证的配置、权限、来源、后台任务和修改记录规则；没有同时维护另一套模型循环或终端渲染器。锁文件增加了产品包依赖；`.gitignore` 为真实源码目录 `src/changes` 增加例外。

升级 OMP 时需重点复核 ToolDefinition 标记、显式发现选项、原生文件语法和快捷键入口。升级 Sandbox Runtime 时需复核生成命令格式、临时目录及 macOS 最终规则顺序，格式不匹配时保持拒绝执行。
