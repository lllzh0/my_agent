# 通用资源开关

更新：2026-10-27。适用于 main 和协作分支的产品入口 `bun run agent`。完整预设、独立会话自动归属及代码扩展仍是后续范围。

## 使用

安装本轮源码改动后，先重启一次正在运行的旧版本。之后在聊天输入框执行：

```text
/resources
```

菜单可逐项开关工具、技能、指令文件（包括显式选择的 AGENTS.md）及自定义/附加提示词文件，也可添加指令、技能文件或目录、附加提示词。原 `/agent` → “修改资源选择” 进入同一个菜单。

墨线界面可按 F3 →「查看当前状态」打开只读概览：顶部显示资源总数及可用、未生效、已关闭数量，下方按技能、指令文件、附加提示词、工具分组。工具按状态合并显示，技能带 `$` 调用名称，文件显示名称与路径。方向键、PgUp/PgDn、Home/End 滚动，Esc 回到菜单；查看和输入文字都不会修改配置。

无需菜单时：

```text
/resources list
/resources off tool:web_search
/resources on tool:web_search
/resources off skill:你的技能名
/resources off instruction:/绝对路径/AGENTS.md
/resources on instruction:/绝对路径/AGENTS.md
/resources reload
```

`list` 显示同样的概览，技能和文件条目保留可直接复制的 ID。工具 ID 为 `tool:工具名称`；技能 ID 为 `skill:技能名称`；`instruction:` 和 `system:` 使用绝对路径，含空格的路径原样写在 ID 后面，不额外加引号。`reload` 重新读取当前已选择的文件内容与技能目录，不重新扫描全局配置，也不从磁盘重新导入整个 config.json。

概览用“可用”“已关闭”“已开启 · 未生效”区分状态。底层 `enabled` 是用户的开关选择，`active` 是当前实际工具集合或已载入的资源元数据。例如 goal 的开关打开后，仍须进入目标模式才能获得 goal 工具；协作分支中的分派工具还受 `/team auto` 控制。技能的“可用”不表示正文已读入，工具可用也不跳过授权与计划模式限制。

## 生效与保存

- 不用重启进程。切换完成后，下一次模型请求采用新的工具声明、技能目录及系统提示词；技能命令和补全同步更新。
- 开关保存在当前 `--home` 对应的 `config.json` 中，新会话及重启后沿用；当前会话资源记录也同步保存。它不是每个项目独立的设置，同一配置目录启动的后续工作区也会沿用选择。
- 仅允许空闲时切换。回答、重试、上下文压缩、排队输入、旁问、后台任务、代码审查、会话/模型切换和协作成员运行期间拒绝更改。持续目标先 `/goal pause`。
- 读取或应用失败时保留原配置；发生部分写盘失败时尝试恢复旧运行状态、配置和会话记录。如果回退本身失败，阻止后续提交并提示退出检查。
- 切换不发送模型请求，不更改授权方式。命令沙箱后续执行会使用新资源的读取范围。

配置仅增加可选的排除列表，不要求迁移旧配置：

```json
{
  "resources": {
    "instructions": ["/绝对路径/AGENTS.md"],
    "skills": ["/绝对路径/skills"],
    "extensions": [],
    "appendSystem": [],
    "disabled": ["tool:web_search", "skill:example"]
  }
}
```

## 边界

1. 关闭资源不会删除已经进入聊天、摘要或历史记录的内容。要避免旧工作流内容继续影响模型，切换后用 `/new` 开空白会话；完整预设会在后续提供独立会话管理。
2. 关闭工具会移除后续请求中的该工具，并拒绝继续调用该入口。但关闭 `write` 并不禁止 `bash` 或 MCP 修改文件；关闭技能/指令也不会禁止通过仍开启的普通读取工具访问它们。访问限制由权限系统管理。
3. 旧会话仍使用已有的严格匹配规则：其他会话的资源配置或文件内容不同，会拒绝 `/resume`；请恢复匹配选择/文件版本，或新开会话。当前被切换的会话会更新自己的资源记录，能在相同配置下重新启动恢复。
4. 只管理已注册的产品工具和显式选择的资源。不自动发现全局/项目 AGENTS、技能、提示词或代码扩展。产品基础系统提示词始终存在，关闭附加提示词不会移除产品行为约束。
5. MCP 的 `mcp_list`、`mcp_call` 等产品入口可像普通工具一样开关；单个 MCP 服务的配置启用/停用仍使用原菜单和重启流程。连接/断开仍可在原 MCP 菜单操作。OMP 可执行代码扩展未开放。
6. 轻量模式本身不加载工作流资源及工具，不能用这些开关绕过轻量模式。

## 复用和验证

工具切换直接使用 OMP `setActiveToolsByName`；系统提示词使用 SDK 已有的动态回调。仅给显式技能列表补充 `session.setSkills(skills)`，复用 OMP 的串行工具注册变更、提示词重建及命令元数据通知；不打开隐式发现。

新增回归覆盖真实产品宿主到本地模拟模型的请求：关闭工具及伪造调用、技能和提示词开关、旧工具快照恢复、新建/冷恢复会话、菜单分派、切换失败回退、并发提交拒绝、外部扩展不能代替人打开资源、重名技能拒绝。协作分支额外验证子实例继承工具排除。沙箱测试在外部运行时接口处检查热更新后的实际规则输入，不宣称真实 macOS 命令执行已验收。
