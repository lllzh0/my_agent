# Windows 原生适配：契约与验证

用户在批次 1/3 期间明确要求优先实现 Windows，并选择“原生 Windows，包含命令执行和新的隔离方案”。随后明确授权系统安装、真实隔离验收，以及使用 `env.local` 的密钥验证 OpenCode Go / DeepSeek V4.1 Flash 最高思考档。已有改动保留；本次不提交、不推送。

本机：Windows 10 x64，Bun 1.3.14。实现范围为产品准备、原生组件、PowerShell、进程树生命周期、本地 MCP、Windows 沙箱适配、权限路径和诊断；不扩展 GUI、多 agent 或 Linux。Windows 使用单独固定的 0.0.81 上游依赖，不替换 macOS 0.0.50。锁文件仅增加该别名及 node-forge；不升级其他项目依赖。

已执行：

- 官方 Windows x64 原生归档完成 SHA-512 校验、选择性提取并实际加载，返回 build version **18.10.3**；发现并处理发行包只有 baseline 文件的边界。
- 分发测试 **5 pass / 0 fail**，包含破损归档、版本、选中成员及链接目录边界。
- 真实 PowerShell 与原生进程管理 **4 pass / 0 fail**：中文、空格、引号和 `$ &` 参数，退出码 7，取消及超时清理子进程树，特殊 Windows 路径拒绝、绝对配置目录及真实 MCP 后代清理。
- 初次只读检查确认系统尚未配置；用户确认后执行安装，账户与 WFP 依赖检查 `errors: [] / warnings: []`。安装跳过整用户目录读取授权，不开放任意 loopback。

首次范围检查包含此前批次 1/3：60 文件、约 2,000 行变更；之后增加真实验收及其暴露的问题修复，无提交生成文件或其他锁定版本升级。上游源码只改绝对配置根解析、抽出的名称校验，以及 Windows stdio 稳定句柄清理。源码回退不卸载系统账户、WFP 和持久 ACL；这些属于独立机器状态，需按上游方式单独管理。

验证期间先遇到 Bun 默认 5 秒测试超时，launcher 测试改用有界 30 秒；Windows 冷启动的子进程就绪等待也从 2 秒调整到有界 15 秒。最终结果不包含此前失败轮。

依赖准备存在环境问题：原先 frozen install 报版本不可用，公开 registry 的精确版本端点实际可用；指定官方 registry 后长时间停留于依赖解析。本机独立 Bun 安装又报告 OTLP tarball 完整性错误，同一官方元数据/归档的独立 SHA-512 校验通过。没有禁用完整性检查。后在仓库外 `E:/myagent/.verification-tools` 用独立 npm 环境准备生产依赖，绕过超时的整包版本索引时使用官方精确归档；三项可选模块包另经 SHA-512 校验提供声明，不启动语音/嵌入模型。项目锁文件没有改用 npm 或重解其他版本。本机实际采用分步准备及忽略的依赖链接，**没有证明全新 checkout 的 agent:prepare 能一次完成**。

额外失败与未闭合项：旧产品宿主 fixture 的多项 MCP 集成测试在 Windows 的 30 秒限时内没有结束；独立 20 秒探针期间尚未发出模型请求，原因未确定，未计为通过。初始 dirs fallback 在宿主默认临时目录报 EINVAL，TMP 指向允许目录后通过。独立 Native PtySession 自动脚本停在初始终端握手，没有首屏；后来工具提供的真实 ConPTY 已完成上表交互，前一自动驱动仍未通过。没有因此宣称完整产品回归通过。

真实验收发现并修复：初版整用户目录 DENY 及私有目录父级 ACE 会触发大量 ACL 继承更新；现在要求专用账户没有整用户目录读取授权，只对授权树内的敏感路径设置 DENY。中断测试的孤立 ACE 通过上游 `acl recover` 清理。还修复了启动器所需 `LOCALAPPDATA` 未传入的问题；只传给 srt-win，沙箱命令仍使用专用账户环境。初次测试受 Codex 外层文件限制影响，后续测试宿主在已授权的外层提升下运行，被测命令仍经过真实 srt-win。

真实模型前两轮验收分别因 ACL 初始化及 120 秒测试截止中断；最终将截止改为 300 秒后自然完成。最高档由本地模型目录的 `low/high/max` 和供应商出站请求共同确认。密钥仅在验证进程内从用户文件读取，未复制进配置、会话或请求轨迹。此次仅为最小命令链路，不替代真实项目任务质量验收。

真实服务的白名单字段证据见 [模型验证 JSON](windows-model-2026-10-28.json)：仅包含模型、强度、HTTP 状态、时间、标准化用量和固定测试结果，没有密钥、完整提示词或思考正文。标准化费用来自 SDK 估算，不是账单证明。

本地 MCP 真实验收未通过。独立固定 `PING` 探针对比 Bun 与 Node 启动 API，经过本机 srt-win 0.0.81 后子程序都读到空 stdin；直接启动则协议初始化成功。移除 PowerShell 中转后仍能复现，因此不将问题仅归因于 shell。普通权限现在启动前拒绝本地 stdio MCP，并明确提示使用 HTTP MCP；不自动切换 full。显式 full 路径让 SDK 直接解析程序与 `.cmd` 参数，已验证真实协议及进程关闭。另观察到 Bun 文件执行会读取私有祖先目录信息，临时测试位置需具备正确的访问条件。

仍独立保留的门槛：本地 MCP 隔离/stdin 修复、全新环境准备、旧宿主集成超时定位和更完整的真实任务效果。arm64 和 macOS 本批未实机回归。WFP 初始化在本机实际报告 `anonymous-loopback` 残余：模拟匿名令牌后的本地连接仍有可达路径；普通连接阻断通过，不能据此称为抵抗恶意本机代码的完整边界。Windows alpha 的已知边界详见 [使用说明](../workflow-agent-windows.md)。
