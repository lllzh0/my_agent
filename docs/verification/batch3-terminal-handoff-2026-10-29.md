# 批次 3：终端交接实现与真实验收

日期：2026-10-29，Windows x64 / Bun 1.3.14 / OMP 18.10.3。批次 2 已提交为 `4ad2f31dc3`；本批实现与文档按用户授权一并提交，提交号见 Git 历史，未推送。以下证据采集于提交前的同一候选版本。

## 实现范围

用户确认本批为“空闲时进程交接、旧会话保存、MCP/后台任务清理、启动失败恢复”。[前置真实启动验收](preset-real-agent-2026-10-29.md) 是冷恢复基线，本页另验运行中交接。

`/preset use ID [--new]` 在同一终端窗口切换独立子进程。目标有旧历史时由用户明确选新建或恢复；当前定义和资源未变时 use 当前 ID 提示已在此预设。定义/资源变更先显示当前快照和新定义，只能新建；不替换已有聊天中的一半工具。

`/resume` 增加其他预设的标签与历史。命名预设恢复统一走交接，复用同一条模型恢复/失败回退路径；legacy 内部恢复保留原进程内规则。此处比原设计的“同预设原生恢复”更统一，减少两种模型协调事务。

命名会话的 manifest 新增可选 runtime/version=1，只保存连接 key、思考强度和计划状态，不保存凭据值。交接和正常关闭时保存；没有新字段的旧会话继续按启动配置恢复。legacy 保留原模型选择规则。目标不继承 full 或临时授权；源计划模式与目标已有计划状态取只读的一侧，不因切换解除。

## 生命周期与共享边界

- launcher 仅通过 Bun 本机 IPC 接收当前子进程的结构化请求，验证进程令牌、请求号、工作区、历史目录和预设归属。stdout、模型回答和工具输出均不是控制通道，模型来源的管理命令继续被拦截。
- 源空闲检查沿用 sessions/SDK 的流式、准入、排队、压缩、重试、BTW、goal、模型/资源/审查/会话状态和后台任务门禁。准备阶段冻结终端输入，可按 Esc 取消；不为切换自动停止用户正在运行的工作。
- 目标先构造完整宿主、检查引用/身份/独占租约，不初始化终端，不调用模型、MCP 或命令。目标没激活时禁止模型提交，不改旧 manifest/runtime 或审计；恢复目标的 SDK 初始化/退出文本通过既有 MemorySessionStorage 暂存。
- 激活时用既有 FileSessionStorage 的原子写入与大小前提发布暂存文本。额外租约跨越内存 writer 关闭/文件 writer 重建，避免放开原会话的独占。被外部改动的文件拒绝发布；取消或准备失败保留原文本。
- 准备成功后保存源会话，复用原生 InteractiveMode teardown 关闭 UI、BTW/协作控制器及产品 runtime；MCP/作业管理器、数据库、模型和轨迹都关闭。源退出 0 才激活目标；关闭确认消息丢失时，成功退出仍是清理结果，不能因此误回退。
- 源清理或目标激活失败后，先回收目标，再从已保存源记录恢复一次；回退失败显示对应平台可执行的恢复命令。未激活的新 UUID 可清理，已有目标不删除；激活过的记录保留。每阶段有有限超时、取消和进程回收。

Win/Mac 共用协议、监督状态机、宿主、存储缓冲及 TUI；仅等待预算与原有 Shell 引用规则区分平台。未改依赖/锁文件、原生隔离或协作分支。底座只新增复用 teardown 的宿主入口，没有另写关闭逻辑。

受控本机 HTTP MCP 通过产品菜单逐次批准连接，服务实际收到 initialize、notifications/initialized 和 tools/list；切离 mcp-a 后收到一次 DELETE。准备及激活前观察为零请求。此项证明产品连接生命周期，不冒充真实外部 MCP 服务质量。Windows 原生隔离仍被系统锁阻塞，本轮没有真实隔离后台命令成功证据；活动/启动中的作业通过共享门禁拒绝切换，不自动杀掉用户作业。

真实检查先发现输入钩子 30 秒超时与源退出未完成：现交接控制器独立于输入钩子持有生命周期，并在 UI teardown 后完成进程退出清理。Bun 纯等待下 AbortSignal.timeout 的计时也改为可回收的显式定时器。未激活写入、IPC 关闭确认丢失和目标外部变化均补专门回归。

## 真实 Go / DeepSeek max 任务

任务与固定版本、许可、独立 oracle 的定义沿用 [前置任务](preset-real-agent-2026-10-29.md)，重新准备修复前源码。使用 env.local 的密钥，实际 launcher、Ink TUI、手动编辑审批和最高思考强度；没有 demo、假模型或 full。

在一个 ConPTY 中完成 coding-a 修复→`/preset use review-b --new`→B 只读检查→`/resume A原ID`→A 从旧聊天回忆备忘标记→正常退出。模型自行修改 index.js、编写 54 行 regression.test.cjs，外部执行该测试退出 0，独立 oracle 从 42/45 变为 45/45。B 与恢复 A 未改变文件，A 保留两条修改记录，B 为零，各一份会话文件。

轨迹共捕获 **14 次**真实请求：6 toolUse、7 stop、1 length，全部 HTTP 200、opencode-go/deepseek-v4.1-flash、reasoning_effort=max。其中主任务与首次 A/B/A 为 11 次；最终存储缓冲版本再从旧 A 切至旧 B、再恢复旧 A，新增两次历史核对和一次终端回顾请求。B、A 均未调用工具即答出各自原标记，最后 launcher 正常退出 0。

length 来自测试配置的 4096-token 输出上限，后续调用继续完成任务；终端回顾请求也计入总数，不能把它们误当恢复问题的回答。恢复核对使用实际包含 A 原标记的回答，而非仅检查最后一条文本。

A 实际请求只含自身指令与 read/write/edit；B 只含自身指令与 read/ls；全组请求中没有另一预设的规则和历史标记。恢复后的 A 使用自己的 coding 连接与 max，而非 B 的 review 连接。两连接仍引用同一个真实 key，本轮不证明不同账号隔离。

对该夹具已有 101 个文件按字节检查实际 key（含 SQLite），0 命中；原始凭据文件不在输出目录内。仓库仅保存 [脱敏结构化记录](batch3-terminal-handoff-2026-10-29.json)，不保存请求/响应正文或密钥。原始轨迹和驱动分别在 `E:/myagent/.verification-tools/real-handoff-2026-10-29/`、`E:/myagent/.verification-tools/handoff-2026-10-29/`。
