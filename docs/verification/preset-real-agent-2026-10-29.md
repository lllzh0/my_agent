## 实际流程与结果

1. 在真实 Windows ConPTY 启动 coding-a；显式 `/effort max`、`/trace on`，提交修复任务。模型读取 index.js，提出两次 edit 和一次 write，均通过真实审批界面逐次允许。
2. 新测试文件审批进入“查看修改详情”，Esc 返回后仍要求批准；此时独立检查文件不存在。随后“仅本次允许”才写入。实际修改只有两个目标文件，生成三条修改记录。
3. 模型完成修复和 60 行回归测试，明确说明未运行任何命令。外部运行它生成的测试退出 0；独立 45 项行为检查由修复前 42 pass / 3 fail 变为 **45 pass / 0 fail**。
4. coding-a `/quit` 退出 0。通过真实 CLI 将工作区默认绑定为 review-b，不传 --preset 启动 B。B 只读检查许可/API/非字符串行为，未获写工具，没有修改记录。
5. B `/quit` 退出 0。保持工作区绑定 B，仅用 A 原会话文件传入 --resume，launcher 正确回到 coding-a。恢复后的模型不调用工具，准确找回 A 原备忘标记和修改文件，并保留“未亲自运行测试”的事实；随后退出 0。
