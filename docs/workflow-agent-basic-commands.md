|---|---|
| `/help` | 产品命令和已选技能，与补全共用清单 |

| `/usage` | 本会话本地 token、估算费用，不查询账户额度或使用重置机会 |
| `/jobs` | 查看托管命令；`output <id> [cursor]` 读日志，`stop <id>` 停止任务 |

| `/goal [set\|show\|budget\|pause\|resume\|drop]` | OMP 原生目标管理、预算与自动续跑；冷恢复先暂停，需人主动恢复 |

## 撤销如何工作

一轮是一次 agent 运行，重试是新的运行。每次处理最近一轮尚未恢复的记录；跳过无文件修改的回答。重复 `/undo` 继续恢复更早轮次。同一轮多次修改同一文件会恢复到该轮起点，新文件删除，原有文件恢复文本和记录的权限，轮次开始前的人工修改保留。`/redo` 是重试同义词，不是恢复撤销内容。

仅覆盖已记入 `ChangeJournal` 的工作区普通 UTF-8 文本修改，包括 `write`、`edit`、`write_report`。shell、Git、MCP、外部服务、链接、二进制和超过既有大小限制的文件不能统一回滚。

有界面时先展示文件列表和差异，关闭预览后批准整批恢复。目标被用户继续编辑时拒绝覆盖；预检冲突时不写入任何目标。会话忙碌、有排队消息/续接任务、后台命令等待批准/准备/运行，以及计划模式下均拒绝恢复；单项恢复菜单共用保护。

排队和异步路径检查结束后、读取当前文件后、实际删除/写入前检查当前状态；输入处理超时后也终止后续恢复。多文件不是磁盘事务：执行中出错可能只完成一部分，保留备份并报告逐项结果。请暂停其他程序对目标文件的并发写入，这些检查不保证系统级原子替换。

恢复后用静态模板通知模型实际改变的文件，聊天不回退，命令本身不请求模型。后续重试能越过撤销通知识别此前的失败回答；这时保留已有工具结果和通知，请模型继续处理更新后的状态，避免直接重放旧工具批次。普通重试沿用 OMP 工具续接。立即取消重试也保留已持久化的撤销通知。

## 上游调查与复用

文件快照、差异、冲突检查、批量恢复和备份复用已有 `ChangeJournal`，权限复用 `Policy`。重试、思考强度、上下文、统计和连接状态重建使用 OMP 会话 API；任务、后台和 MCP 使用已有产品模块。没有新增依赖或 Git 快照引擎。

查阅了 [pi-rewind](https://github.com/arpagon/pi-rewind) 的按轮选择、恢复前预览和“只恢复文件”流程。它依赖 Git 检查点及 Pi 扩展接口；本产品已有支持非 Git 工作区的文本记录，因此没有直接安装它。也查阅了 [OpenCode revert](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/session/revert.ts) 的空闲保护与快照边界，其会话服务不能直接作为 OMP 模块移植。

## 复查发现的边界

- OMP 输入钩子默认 30 秒后继续分派原文本。停在帮助、菜单或预览较久会漏拦。产品现显式要求失败时消费输入，等待人的对话暂停计时；实际工作保留超时及取消信号。默认 OMP 行为不变。
- 只在异步检查之前检查模式仍有间隙。现于检查结束和实际写入前同步复查；强制在路径解析中切到计划模式时不恢复文件。
- 仅监听新用户提示会使恢复后的多次重试写入相同轮次。现按每次 agent 启动生成独立记录；测试跨进程三次尝试后只撤销最后一次。
- 自定义撤销消息原先挡住原生重试识别失败尾部。现允许指定通知类型，保留通知及工具配对结果；取消重试后通知仍在当前分支和磁盘中。
