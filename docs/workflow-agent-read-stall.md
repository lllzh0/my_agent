## 继续核对根因：请求重建与响应取证

用户进一步要求查明原因，随后说明尚未再次尝试。因此当前只有一次异常样本，不能称为稳定复现，也不能把 `high` 思考档位认定为原因。

从原始会话读取截至第一次 `read` 结果的五条消息，在新的临时目录内运行完整产品 `openHost`、原生 Agent 续接、SDK 上下文转换与 DeepSeek HTTP 序列化；请求只发往本机假服务。结果见父工作区 `artifacts/omp-read-stall/payload-audit.json`，复现脚本为 `validation/delivery/read-stall-payload.ts`。

| 核对项 | 当前代码重建出的请求 |
|---|---|
| 消息顺序 | system → user → assistant → tool → assistant → tool |
| 写入前的思考内容 | 234 字符，逐字保持一致 |
| 读取前的思考内容 | 12 字符，逐字保持一致 |

[DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode#tool-calls)要求带工具的后续请求完整回传 `reasoning_content`。本地重建符合这项要求，未复现这类内容丢失。重建时使用相同会话历史和当前代码，但身份、临时工作目录及 HTTP 服务不同；它不是事发时的原始 HTTP 记录，不能证明历史请求的每个字节或服务端内部状态。

目前可确认的原因链为：文件已读取 → agent 发起后续模型响应 → 该响应没有完成 → 300 秒的默认等待上限尚未到达 → 用户约 96 秒时取消。前一次调整的错误分类与目录优先级都不解释模型为什么停止完成响应。

为下一次复现补上取证：模型错误或取消时，从 OMP 已有的响应缓冲区提取时间、HTTP 状态、完整 SSE 事件数量、思考/文本字符数、结束标记以及 agent 实际解析出的内容数量，写入当前会话状态目录的 `model-stream.json`。每次异常覆盖上一份摘要。不会新增远端请求，也不保存请求头、提示词、模型正文或工具参数。

这项记录从重启后的新进程生效。使用退出时显示的原会话恢复命令启动，以保留原工作目录，再继续读取已存在的 probe.txt；若再次停住，按 Esc 再正常退出，摘要就会保留。诊断读取可使用：

```sh
agent_diagnostic_home="${MY_AGENT_HOME:-$HOME/.my-agent-omp}"
ls -t "$agent_diagnostic_home"/state/*/model-stream.json
```

判断时比较 `wire.contentChars` / `wire.reasoningContentChars` 与 `consumed`，并检查 `wire.finishFrames` 和 `wire.doneSentinels`。若完整响应已到达而 agent 未消费，继续查本地解析；若只有少量响应且没有结束标记，则继续调查服务、网络或尚未形成完整 SSE 事件的传输，不能直接断言供应商故障。缓冲区只保留有限事件，淘汰和截断计数必须一起看。

新增测试已复现旧版本缺少此摘要，并验证读取完成后的半途响应、取消落盘、正文不进入摘要、旧请求不污染新请求，以及已收到内容与已消费内容的差异。真实服务的具体停顿原因仍待新的响应证据。
